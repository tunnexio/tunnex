# ⛔ 0. THE RENDER FLOOR. FIRST, BEFORE ANY COPY.

Read from `docs/EPIC-15-zero-trust-for-ai-agents.md` §0 before a word of this paper's copy was written.

> ## **UNDER PROMPT INJECTION, AUTHENTICATION IS INTACT AND AUTHORIZATION IS INTACT. ONLY *INTENT* IS
> ## CORRUPTED. ZERO TRUST BOUNDS THE BLAST RADIUS OF A CORRECTLY-AUTHENTICATED PRINCIPAL. IT DOES NOT
> ## DETECT INJECTION.**

**Two claims this surface may never make, in any copy, at any size:**

| forbidden claim | why |
| --- | --- |
| ⛔ **detection** — "catches", "blocks", "prevents" a manipulated request | The product does not inspect intent. A boundary **limits what a request can reach**; it does not know the request was manipulated. Claiming otherwise is a render-floor violation **at product scale** — a promise made to people who cannot check it |
| ⛔ **per-tool control** — "allow this agent to call *this MCP tool*" | Enforcement is **five fields**: `SrcIP, DstCIDR, Protocol, PortLow, PortHigh`. A tool name is not among them and cannot be. Teleport does per-tool; **we do not**, and the claim is checkable and false |

⚠ **The honest verb is REACH.** This surface says *which agents may reach which destinations*. It never says
*which actions they may perform there*, because the enforcement plane cannot see actions.

**Permitted, because they are true:** *bounded* · *reachable* · *attributable* · *revocable* · *unattributable*.

# 1. ⛔ THE HARD CONSTRAINT — NOTHING HERE REACHES THE COMPILED ARTIFACT

`hashAllow` is **`{SrcIP, DstCIDR, Protocol, PortLow, PortHigh}`** (`policyspec/hash.go:15-21`), and
**`dst_kind` never reaches the agent.** That is the epic's central measured finding, and it cuts both ways:

- it is why the **destination half already shipped** — an MCP server is expressible today;
- it is why **a new marker is invisible to enforcement by construction.**

> ## **THIS SURFACE IS A NAMING AND PRESENTATION LAYER OVER WHAT ALREADY SHIPS. IT IS NEVER A SECOND
> ## ENFORCEMENT PATH.**

⛔ **If a design requires touching `policyspec`, it is the wrong design and it returns as a decide-item.**
The test is mechanical: **does `make generate` change `CanonicalHash` inputs?** If yes, stop.

⚠ **And this is a gift, not a limitation.** A marker outside the compiler cannot desync the artifact, cannot
bump `RequiredVersion`, and cannot brick a gateway that has not been updated. **The cheapest place to be wrong
is outside the thing that must be right.**

## 2.2 Persisted but **NOT SERVED** — the gap

| fact | where | problem |
| --- | --- | --- |
| ⛔ **`devices.kind = 'agent'`** | S15.2 `0067` | **Not in the device DTO.** Served keys are `approved_by, created_at, health_*, id, name, needs_reexport, node_id, online, platform, public_key, status, user_id` — **no `kind`** |
| `node_join_tokens.issued_by` | S15.2 `0066` | not served anywhere |

⛔ **THE AGENT MARKER EXISTS IN THE DATABASE AND IS INVISIBLE TO EVERY CLIENT.** This is the who-reads-this
probe failing on a column S15.2 added — the same defect as `owner_email` in S15.1, one table over. **A device
list cannot distinguish an agent from a laptop.**

## 2.3 Does NOT exist

⛔ **An MCP server is INDISTINGUISHABLE from any other port-scoped resource.** Served resource keys are
`cidr, created_at, id, name, org_id, port_high, port_low, protocol, updated_at` — **no type, kind, or label.**
Confirmed, as expected.

**The cheapest honest marker:** a **nullable free-text `kind` (or `label`) on `resources`**, set by the
operator, defaulting to NULL.

- ⚠ **It must be an operator's assertion, never an inference.** The product cannot detect that something
  speaks MCP. A field that *claims* detection would be §0's violation in miniature. The copy is *"what is
  this?"*, answered by a human.
- ⛔ **It lives entirely outside the compiler.** `resources` feeds `dst_cidr/protocol/port_*` into
  `hashAllow`; a `kind` column is simply not read by the compiler, so it cannot reach the artifact **by
  construction rather than by discipline.**
- ⚠ **Enum or free text is a decide-item** (§5.2). An enum is greppable and constrains copy; free text does
  not require a migration every time a new protocol appears.

### 5.2 The resource marker — enum or free text? And is `kind` the right word?
**Recommend a nullable free-text `label`.** ⚠ `kind` collides with `devices.kind`, which is a *structural*

### 5.3 ⛔ **RULED: SERVE `devices.kind`.**

**The reason:** the alternative is worse than a contract change — **a column persisted by the story that
added it and read by nobody.**

> ## **THAT IS THE SECOND INSTANCE IN TWO STORIES** — `owner_email` (S15.1) and `kind` (S15.2), each
> ## persisted by the story that added it and served by neither. **Shipping a third would make it a habit
> ## rather than a class.**

#### ⚠ THE CONTRACT CHANGE, STATED HONESTLY RATHER THAN BURIED AS "ADDITIVE"

**Every device payload widens, including consumers that never heard of agents.** ⛔ *Additive* is a property
of the schema, not a guarantee about consumers — so the consumers are named and measured:

| consumer | what it does with an unknown field | measured |
| --- | --- | --- |
| **`apps/cli`** — generated Go client (`apps/cli/internal/api/api.gen.go`) | **ignores it.** `encoding/json` is permissive by default and **`DisallowUnknownFields` appears nowhere in the repo** | grep: zero hits |
| **`packages/shared`** — generated TS types (`api.d.ts:2639`) | **structural types only.** An extra property is present at runtime and unreferenced; no runtime validator sits between | read |
| **the API's own response path** | **no response validation** — the middleware validates *requests* against the spec, not responses | grep: zero hits |
| **`apps/web`** | regenerated from the spec in the same commit; a field it does not render is inert | — |

⚠ **So the blast radius is genuinely nil — and it is nil for a REASON, not by assumption.** Had any consumer
used strict decoding, this would have been a breaking change wearing the word *additive*.

### 5.4 ⛔ **RULED: NOT ENTERPRISE-GATED.**

**The reason:** this surface **describes behaviour that ships in BOTH editions.** Gating a description of
open-edition behaviour **hides the product from the people running it.**

⚠ **AND THE SHAPE IS ONE THIS REPO HAS ALREADY PAID FOR.** S14.5 found the open edition shown an **upsell for
an all-editions capability** — a client-invented boundary the server does not have.

> ## **GATING THIS WOULD BE THAT DEFECT, DELIBERATELY.** The edition boundary is the server's to state; a
> ## surface that invents one is lying about the product in the direction of a sale.

### 5.4 Is this enterprise-gated?
⚠ **Unlock-then-opt-in is the standing convention**, but this surface *describes* what already ships in both
editions. **Gating a description of open-edition behaviour would hide the product from the people running

# 8. ⛔ D-S15.3-1 — **RULED: "AGENT" BECOMES A REAL DISTINCTION. A MARKER AT ENROLMENT.**

**Founder-ruled after the creation question exposed that the distinction does not exist.**

## 8.1 The measurement that forced it

| check | result |
| --- | --- |
| `Enroll` | **one function**, no kind: `Enroll(ctx, rawToken, csrPEM, nodeName, agentVersion)` |
| `node_join_tokens` columns | `issued_by, org_id, id, token_hash, expires_at, consumed_at, consumed_node_id, created_at, node_name` — **no type marker** |
| what gates `allocateAgentDevice` | **`if tok.IssuedBy.Valid`** — and nothing else |

> ## **SO EVERY GATEWAY ENROLLED WITH AN ISSUER-CARRYING TOKEN GETS A `kind='agent'` DEVICE ROW.** Not
> ## agents. **Every gateway.** An agent, today, *is* a gateway — the code contains no other answer.

⛔ **The section therefore lists every issuer-enrolled gateway under a heading that says "AI agents", and
the heading is false for most of them.** That is the render floor failing at the level of the screen's own
title — which is why shape **A** (document the existing flow) was **not available**.

**C** (a create path on this screen) was refused for the one-truth risk: **two places emitting enrolment
commands**, when the ceremony already exists on Gateways.

## 8.2 The ruling

**The join token carries the answer.** The operator says **what they are enrolling at the moment they mint
the token** — which is *also* the moment ownership is captured.

⭐ **The flow already carries the issuer; it gains one more fact at the same instant.** No new ceremony, no
second command, no duplicated surface.

**Shape of the marker (to be built, not yet designed in detail):**

- a column on **`node_join_tokens`** — the token is where the operator's intent lives, and it is consumed
  exactly once;
- carried onto the **node** at enrolment, the same way `issued_by` becomes `owner_user_id`;
- ⚠ **and the `devices.kind='agent'` row becomes CONDITIONAL on it**, instead of on "the token had an
  issuer". That is the line that currently makes every gateway an agent.

⛔ **NOT a marker on `devices` alone.** The device row is a consequence; the decision happens earlier, and a
marker downstream of the decision cannot answer *what was this meant to be*.

## 8.3 ⛔ THE MIGRATION QUESTION — ANSWERED IN THE PAPER, HELD FOR RULING

**Every gateway enrolled since S15.2 with an issuer-carrying token already has a `kind='agent'` device row
and is not an agent.**

**Scope, measured now:** `2` agent rows exist, **both seeded by SQL**, `0` from real enrolments — because
this rig's only real enrolments were the walk's, and those rows were deleted. ⚠ **The number is small only
because the feature is days old.** On any deployment that has enrolled gateways since S15.2, every one of
them is currently an "agent".

**Shapes — none picked:**

| shape | what it does | cost |
| --- | --- | --- |
| **1 — treat existing rows as NOT agents** | the marker defaults absent; existing `kind='agent'` rows are re-kinded to `human` or dropped | ⚠ destroys the `/32` those rows hold — and that address is a real allocation the gateway may be using |
| **2 — treat them as agents** | grandfather them | ⛔ makes the heading permanently false for exactly the rows it was false for; the defect becomes the migration |
| **3 — mark them UNDETERMINED** | a third state: "enrolled before the distinction existed" | honest, and it adds a state every consumer must handle — the `unknown` that never goes away |

⛔ **AND UNTIL THIS IS RULED, THE SECTION MUST NOT KEEP CALLING THEM AGENTS.** A heading that is currently
false is not to be quietly softened — the fix is the marker, not the wording.

# 9. ⭐ TWO FINDINGS THIS RULING PRODUCED — the most transferable things in the story

## 9.1 ⛔ A CAUSE INFERRED FROM A SYMPTOM'S NAME IS NOT A DIAGNOSIS

`walk-agent` and `walk-agent2` — **ordinary gateways** — appeared in an AI-agents list. **That was the
defect showing itself.**

**I read it as walk residue and deleted the rows.**

> ## **THE TELL WAS AVAILABLE AND READ AS NOISE.** They were named `walk-*`, so "walk debris" was the
> ## available story, and it fitted. It explained the *presence* of the rows and explained away the
> ## *question they were asking* — why is a plain gateway in this list?

⛔ **Deleting them removed the evidence rather than the cause.** The next reviewer would have seen a clean
list of two seeded rows and no reason to ask anything.

⚠ **And no measurement re-opened it — the founder's question did.** *"How does anyone create an agent?"*
is a question about a flow, and it could only be answered by tracing the flow, which is what surfaced the
missing distinction. **A symptom I had already filed as understood.**

**The check:** when a row is explained by *where it came from*, ask separately whether it should have been
able to arrive there at all. **Provenance answers "why is this here". It does not answer "should this be
here".**

## 9.2 ⛔ A FIXTURE ASSERTING A SHAPE THE PRODUCT CANNOT PRODUCE CONCEALS THAT THE PATH IS MISSING

`mcp-agent-prod` and `mcp-agent-departed` were **seeded directly by SQL and came through no flow at all.**

> ## **A FIXTURE THAT FAKES A SHAPE DOES NOT MERELY FAIL TO TEST THE PATH — IT CONCEALS THAT THE PATH IS
> ## MISSING.** The screen looked complete because the data looked right. The absence of any way to create
> ## an agent was invisible precisely because agents existed.

⚠ **Third fixture-fidelity instance in three stories, and the worst direction yet:**

| story | fixture | what it hid |
| --- | --- | --- |
| S15.1 | seeded into an org with no switcher | a state that existed and could not be reached |
| S15.2 | keys `wg` would reject | a peer path that could not have worked |
| **S15.3** | **rows no flow can produce** | ⛔ **that the flow does not exist** |

⚠ **Each is more expensive than the last**, because each hides something further from the data and closer to
the product. **The first hid a state, the second hid a code path, the third hid a missing feature.**

**The check, stated as a question a fixture must answer:** *what sequence of product actions would produce
this row?* ⛔ **If the answer is "none", the fixture is not a fixture — it is an assertion about a product
that does not exist yet.**

# 10. ⛔ THREE RULINGS THAT REVERSE EARLIER ONES — recorded with both reasons, not edited away

**Founder-ruled after §8's measurement changed what an agent *is*.**

## 10.1 ⛔ NAV — **REVERSED. A TOP-LEVEL DESTINATION, IN `NETWORK`, BESIDE KUBERNETES.**

**What §3 ruled, and why it was right at the time:** *B — a section inside Devices*, because **the schema
says an agent is a `devices` row**, and B was the only option that did not invent an organising principle
the model lacked.

> ## ⛔ **THE MEASUREMENT BROKE THAT PREMISE.** An agent is a **GATEWAY**, enrolled on Gateways, that
> ## *acquires* a device row. **The row is an artifact of attribution, not the thing itself.** Devices was
> ## never its home — B was reasoning correctly from a fact that turned out to be a consequence.

⚠ **The old ruling stands in the record.** It was not wrong reasoning; it was right reasoning over a
premise that had not yet been measured. **Editing it away would hide that the premise was the error, not
the argument** — and the next person would learn nothing from a clean paper.

**KUBERNETES IS THE PRECEDENT, AND IT IS THE RIGHT ONE:** a capability with **its own enrolment path, its
own destinations, and its own screen**. `NETWORK` currently holds **Gateways · Sites · Routed ranges ·
Kubernetes** (`AppShell.tsx:42-53`) — ⭐ **that group is where things you ENROL live**, which is exactly
what an agent now is.

## 10.2 ⛔ EDITION — **REVERSED. IT IS AN ENTERPRISE FEATURE.**

**What §5.4 ruled, and why it was right at the time:** *not gated*, because the surface **described
behaviour that ships in both editions**, and gating a description of open-edition behaviour hides the
product from the people running it.

> ## ⛔ **THAT WAS TRUE OF A SECTION DESCRIBING DEVICES. IT IS NOT TRUE OF A NAMED PRODUCT CAPABILITY WITH
> ## ITS OWN ENROLMENT PATH.** The founder is defining the boundary, **and the boundary is the server's to
> ## state** — which is the same principle §5.4 invoked, now pointing the other way.

⚠ **§5.4's S14.5 warning still binds, and is not contradicted:** the defect there was a **client-invented**
boundary the server did not have. Here the server states it. **The rule was never "do not gate" — it was
"do not let the client invent a gate."**

**How it must be gated:**

- ⛔ **permission BEFORE edition**, per `TestEditionGateNeverPrecedesPermissionGate`
  (`http/edition_gate_order_test.go:53`) — which harvests the gate-helper names from source rather than
  hardcoding them, so a new helper cannot slip past.
- ⛔ **the open edition sees ABSENCE** — not a styled-away control, not an upsell, not an error.
- ⚠ **`403 edition_required` is a SUCCESSFUL REFUSAL, not a failure.** Folding it into the failed state is a
  defect this repo has already paid for: the surface would render "could not load" for a server that
  answered correctly, which is the load-failed/none confusion with a different label.

**How many agents. How many unattributable.**

⛔ **NOT a health verdict, and NOT a claim about what they are doing.** The card counts principals and names

# 11. THE MARKER — **BUILT** — AND THE MIGRATION, **HELD**, IN ONE SECTION

⛔ **THEY ARE NOT SEPARABLE.** The moment `kind='agent'` becomes conditional on the marker, **every existing
`kind='agent'` row was set by the old condition and is wrong.** They are gateways that acquired the row
because their token carried an issuer.

## 11.1 The marker, as built (`0069`)

| where | column | shape |
| --- | --- | --- |
| `node_join_tokens` | **`enrols_kind`** | `NOT NULL DEFAULT 'gateway'`, `CHECK IN ('gateway','agent')` |
| `nodes` | **`enrolled_kind`** | **nullable** — carried from the redeemed token; **NULL = UNDETERMINED** |

⭐ **Named for what it is: the operator's declaration of what they are enrolling**, captured at the same
instant as the issuer — because minting a join token is the one act that says both **who is accountable**
and **what is being brought online.** No new ceremony, no second command.

⛔ **ABSENCE IS THE CLOSED STATE.** `NOT NULL DEFAULT 'gateway'` on the token: a caller that has never heard
of agents cannot mint one by omission. **A nullable marker read as "agent" would be the same fail-open one
column over.**

### The condition — **both, not one replacing the other**

```go
if tok.EnrolsKind == enrolKindAgent && tok.IssuedBy.Valid {
```

⚠ **The marker says this was MEANT to be an agent; the issuer says an accountable human exists.** D14 has
not changed. Dropping the issuer check would let a marked-but-unowned token produce an **unattributable
agent** — precisely what D14 ended.

**Three reds, mutation-proven one at a time:**

| assertion | mutation that breaks it |
| --- | --- |
| a marked, issuer-carrying token **produces** an agent | — |
| ⛔ an **unmarked** issuer-carrying token does **NOT** | reverting to `IssuedBy.Valid` alone — **FAILS** |
| a marked token with **no issuer** does **NOT** | dropping the issuer check — **FAILS** |

⛔ **The second is the whole fix.** A test proving only the first would pass on the old code unchanged, and
this would be a refactor.

Plus: the schema default is asserted directly (a token minted without naming a kind comes back `'gateway'`),
and **UNDETERMINED is asserted as reachable** — a node inserted without the column comes back NULL.

### Census by INPUT, not by function name

| input | sites | verdict |
| --- | --- | --- |
| **reasoning *issuer implies agent*** | **exactly one** — `service.go:338` | **that was the defect; it is the line changed** |
| readers of `kind='agent'` | the `0067` partial unique index · `agentview.ts:53` | ⚠ both read the **result**, not the condition — **still correct** |
