# S20.5 API review fixes

Status: locked implementation decision for review findings 2 and 16 only.

## Finding 2 — lifecycle remint authorization

`RemintNodeLifecycleClaim` returns the same raw gateway join credential as the
ordinary enrollment path. It therefore requires the intersection of the two
existing authorities:

- `k8s:manage` (`rbac.PermK8sManage`) for Kubernetes lifecycle scope; and
- `org:update` (`rbac.PermOrgUpdate`) for raw gateway join-token minting.

Both checks happen before request-body validation, claim lookup, or token
minting. Owner and Admin principals retain the existing human enrollment path.
An Operator machine remains able to perform non-secret lifecycle operations but
cannot remint a gateway credential. No new permission or role grant is added.

Proof is a dedicated handler regression that fixes the route capability
intersection as a behavior invariant: Operator-machine requests are forbidden
before malformed-body handling, while Owner and Admin requests pass the two
authorization gates. The test must not expose claim existence or a token.

## Finding 16 — base-authority prior-read failure

The ordinary-base pending-transition read and latest-authority read use
separate, non-shadowed error values. Any prior-read conflict or database error
returns before a delivery insert, pool insert, or authority-revision advance.

Proof is dedicated store coverage for conflict and arbitrary read failures with
zero new authority writes, plus the unchanged valid issuance/replay behavior.
