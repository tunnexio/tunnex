## Locked behavior

- Fresh enrollment with no existing claim proceeds.
- Enrollment with an existing claim proceeds only when its canonical non-nil
  organization and lifecycle-claim annotations exactly match supplied values.
- Missing, partial, malformed or mismatched existing ownership refuses before
  Helm can apply new labels or annotations to that PVC.
- Explicit tokenless legacy reuse remains separate and is not silently treated
  as fresh enrollment or zero-touch CP identity verification.
- Preserve CLI compatibility and its stronger control-plane claim verification.
- No API, schema, credential, runtime networking or HA change. A need for any
  new protocol or recovery state machine is a stop-and-report condition.

## Implementation and proof boundary

Use mandatory chart-render validation with live PVC lookup, not an optional
hook that can be skipped with `--no-hooks`. Normal Helm install/upgrade can
query the cluster; offline `helm template` output is not live ownership proof.
Cluster read failures must fail closed, never masquerade as absent storage.

Test fresh, matching, mismatched, malformed and legacy cases through actual Helm
rendering with controlled lookup responses. Run existing chart/CLI compatibility
checks and one bounded AWS proof using disposable resources only. Preserve the
working gateways and existing recorded packet/HA evidence. Commit redacted
evidence; do not store credentials, tokens, kubeconfigs or private keys.

Review this change independently once and hold concrete findings for disposition.
Only report the direct-Helm finding closed after implementation and its actual
tests support that claim. Other PR #56 review holds remain separate.

schema or credential changes. Mandatory lookup precedes PVC rendering; existing
