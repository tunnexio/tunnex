# Workspace skill delivery decisions

Public key admission slice: creation requires1–7 user SSH public keys, leaving one slot for the worker's dedicated readiness probe key. This bounded maximum is an implementation choice, not a prior exact user requirement. Normalize permitted ordinary Ed25519/ECDSA/RSA>=2048 keys, strip comments, sort and reject duplicates/options/certificates/private-key text. Persist immutable normalized public keys in the sandbox intent and idempotency hash. UI asks only for `.pub` contents; it cannot read local private keys. Worker mount preparation uses this persisted set plus a dedicated probe public key, never a supplied replacement user set. Legacy zero-key sandbox rows remain stored but cannot start; no live row migration/key assignment is performed. Updating admitted keys is deferred; explicit recreation is required in this MVP.

Next transport slice: a trusted worker supplies already prepared absolute retained-workspace, read-only skill and read-only SSH-server asset directories through an injected per-sandbox resolver. Provider verifies mount sources as private real directories without symlink path components, uses structured Podman mounts and keep-id uid/gid1001 mapping, and binds their exact normalized paths/digest to a provider label. Inspection must verify actual mount source/destination/read-write modes, not just labels; mismatched recovery fails closed. No human request supplies a host path. Runtime/bootstrap credentials are excluded from these workload mounts. The source image still idles unless this terminal-assets composition is explicitly selected. No production resolver is wired. SSH-key generation/persistence and network setup are separate remaining work; mounts are source integration, not actual Linux qualification.

Terminal publisher reserves an exclusive0700 staging directory through the trusted root, writes a generated Ed25519 server key and normalized approved user/probe public keys as0600, fsyncs and atomically publishes `terminal`. Retry verifies the fixed sshd configuration, identical public-key set and valid persisted host key without rotation. Reject key options/certificates/DSA, duplicate/oversized key lists and symlink/nonregular assets. No private human key is read or copied; a trusted control worker must supply only authorized public keys, including a dedicated probe public key. Private host identity is for this sandbox's unprivileged SSH server and is not a CP/runtime credential. It is readable by that sandbox uid, as required by this minimal non-root sshd composition; future process-level key separation is not claimed. Fixed configuration refuses passwords/forwarding/user rc/environment, accepts only sandbox, and uses the preloaded SFTP executable. Actual non-root OpenSSH/base-image behavior still needs Linux qualification.

Podman option syntax and keep-id mapping checked against [official run documentation](https://docs.podman.io/en/latest/markdown/podman-run.1.html). Readonly structured nonrecursive/private bind mounts avoid automatic recursive chown and nested host mount exposure; only the two explicitly bounded tmpfs mounts are requested. No security policy disables or mount relabeling are added.

Implemented composition: `PrepareCreationAssets` holds the lifecycle lease/current admission, publishes selected skills and terminal before provider creation, and refuses rewriting bound provider mounts. A private fsynced atomic control manifest binds sandbox/spec and immutable content digest outside the workload. `FilesystemAssets` reads only UUID children of the pre-opened trusted root, verifies exact workspace/terminal/content-addressed skill paths and content before recovery. Missing/tampered key or manifest refuses; no automatic key rotation, credential renewal, replacement runtime or new peer occurs. Empty skill selections still publish a stable empty skill directory. Workspace user files are excluded from the immutable digest and preserved across retry. No production resolver/SSH-key admission route or network adapter is wired yet.

Deliver selected instructions/configuration as inert files, never package installs, shell input or privileged hooks. The trusted coordinator opens an exclusively owned per-sandbox workspace root before workload access; the writer receives this `os.Root` capability rather than a user-supplied host path. Workspace ownership/mounting and uid1001 access are still qualified-adapter responsibilities. No ambient filesystem, network, secret or container socket access is added by the writer.

Validate the complete bounded bundle before writing: at most32 files (16 selections), canonical UUID paths `skills/sandbox-<revision>/SKILL.md` and `config.json`, no duplicate/missing pair, no traversal or symlinks, bounded contents and exact SHA256. Sort path/digest manifest for stable bundle identity. Stage under a fresh generated owned directory and atomically rename to a content-addressed delivery directory. Existing complete matching delivery is idempotent; changed, incomplete or symlinked content fails closed. Never overwrite existing delivery or modify a user's unrelated workspace files. Cleanup removes only the generated staging directory owned by this call. Concurrency is serialized by the existing sandbox lifecycle lease; the root is inaccessible to workloads during delivery.

Returned local content receipt is not network/terminal readiness. Actual provider mount delivery, retained-versus-ephemeral workspace lifecycle, current selection/revocation recheck, local-agent discovery and Ready binding remain integration work. Test normal delivery/retry, changed content, symlink/path/digest rejection and unaffected unrelated files using disposable local temporary directories. No live pilot filesystem or credential access.

It verifies exact content on retry, refuses symlinks/missing/changed files and preserves unrelated workspace entries.
