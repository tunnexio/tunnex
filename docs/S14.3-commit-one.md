## B2 — TOASTS WITH UNDO — **THE DECIDE-ITEM, ANSWERED WITH MEASUREMENT**

> *"An undo on a destructive verb that the server already committed is a lie."*

**So the question is measurable: for which actions can the server return the SAME OBJECT to its PRIOR STATE?**

**Measured:** 16 `DELETE` paths in `openapi.yaml`; **51 audit actions at call sites**; the audit vocabulary
contains **9 inverse-verb pairs**.

**Inverse verb existing is NOT sufficient**, and this is the sharp part. `policy.rule_created ↔
policy.rule_deleted` is a pair, but **re-creating a deleted rule produces a NEW rule id** — a different object,
audited as a creation. That is not an undo; **it is a new grant that happens to look like the old one**, and on
an access-control surface those are not the same thing.

### PROPOSED CRITERION — TWO conditions, both required

> **1. An inverse operation exists in the API, and**
> **2. it returns the SAME OBJECT IDENTITY to its prior state.**

| action | inverse | same identity? | **undo offered?** |
|---|---|---|---|
| `policy.rule_disabled ↔ rule_enabled` | `PATCH .../policies/{ruleId}` | **yes** — same `ruleId` | **YES** |
| `org.zero_trust_disabled ↔ enabled` | `PUT .../zero-trust-mode` | **yes** | **YES** |
| `org.device_approval_disabled ↔ enabled` | `PUT .../device-approval` | **yes** | **YES** |
| `org.ovpn_disabled ↔ enabled` | org setting | **yes** | **YES** |
| `mfa.enforce_disabled ↔ enabled` | org setting | **yes** | **YES** |
| `user.deactivated ↔ reactivated` | member state | **yes** | **YES** |
| `group.member_added ↔ removed` | membership | yes, **but** | **NO — see below** |
| `policy.rule_created ↔ deleted` | re-`POST` | **NO — new id** | **NO** |
| `resource.created ↔ deleted` | re-`POST` | **NO — new id** | **NO** |
| `group.created ↔ deleted` | re-`POST` | **NO — new id** | **NO** |
| `machine.credential_issued ↔ revoked` | re-issue | **NO — new secret** | **NO** |
| `device.revoked` | — | **revocation is a FULL SWEEP** (peer slot + pool address + telemetry) | **NO** |
| `org.deleted` | — | none | **NO** |

**`group.member_added/removed` is excluded for a second, different reason:** for an **IdP-synced** group the
reconciler is **fail-static and authoritative**. An undo there would be **reverted by the next sync**, so the
user would see a success toast and then watch the change disappear. **An undo the system will fight is worse
than no undo.**

### THREE PROPERTIES OF THE UNDO, all of which follow from the above

1. **UNDO IS A REAL API CALL, AUDITED AS ITS OWN ACT** — `policy.rule_enabled` with its own actor and
   timestamp. **Never a client-side "put the row back".** The audit log must never imply the first act did not
   happen.
2. **UNDO CAN FAIL, AND ITS FAILURE IS LOUD.** It is a network call. A silent failure would leave the user
   believing they reversed something they did not — **strictly worse than the original mistake**, because they
   have stopped worrying about it. Three states: offered → in-flight → **succeeded / FAILED-with-retry**.
3. **A TOAST IS NOT A RECORD.** It disappears. **The audit log is the record**, and nothing may exist only as a
   toast.

**FOR EVERYTHING ELSE: NO UNDO, AND A CONFIRM INSTEAD.** Where the act cannot be reversed, the honest
affordance is **before**, not after. Destructive confirms already exist in the product (`disableConfirmText`,
`modeEnableConfirm`) — this slice makes them a primitive rather than adding a false second chance.

**PROPOSED, and mechanical: `UNDOABLE_ACTIONS` is DATA, exported and asserted** — the same shape as S14.1's
`ok` reservation. A `toast()` call requesting undo for an action not in the set **fails a test**, so the
criterion cannot be quietly widened by whoever builds the next screen.

**DEMONSTRATION:** the Access rules enable/disable toggle (F3, already shipped) — the measured, genuinely
reversible pair.

## B3 — MOTION (MIT, pinned) — **`prefers-reduced-motion` AS A GATE, PROVEN TO REJECT**

**Measured: `motion@12.43.0`, MIT, 683,139 bytes unpacked.** Ruled in EPIC 14: never critical path, CSS-first,
lazy, degrades to no animation.

**⚠ A MEASURED OBSTACLE, surfaced now rather than discovered mid-build: jsdom does not implement
`window.matchMedia`.** A test that rendered a component and asked whether reduced motion was honoured would
**throw or silently no-op** — the jsdom-has-no-layout-engine problem again, one media query over.

**PROPOSED — the S14.2 shape, reused because it worked:**

```
motionAllowed(prefersReducedMotion: boolean): boolean      // pure, no DOM — unit-tested both ways
useMotionPreference()                                       // reads matchMedia ONCE, at the app edge
<Animated>                                                  // the ONLY component that may animate
```

Gated three ways, each with a mutation:

1. **the pure decision** — `motionAllowed(true) === false`;
2. **a SOURCE SCAN** — no `transition-*` / `animate-*` class and no `motion` import outside the sanctioned
   module *(the `ok`-reservation scan, re-aimed; currently 2 offenders, both benign, both converted)*;
3. **the render** — with the preference injected as `true`, `<Animated>` emits **no** animation props.

**Mutation: make `<Animated>` ignore the preference; assertion 3 must go red.**

# GROUP C — DATA VISUALIZATION

## C1 — LIBRARY vs HAND-ROLLED SVG: **PROPOSED HAND-ROLLED, and the measurement is the argument**

Of the ten named types, a general charting library covers **at most three** (donut, histogram, bar). It covers
**none** of the force-directed network map, the bipartite access-flow, the address-space heatmap, or the
radial device fabric. **So a library would be added for three and the other seven hand-rolled anyway — which
is precisely how "a design system acquires four charting libraries."** Against a **352.64 kB** bundle, a
charting dependency is a large fraction added for a minority of the need.

## C2 — **THE RENDER-FLOOR AUDIT, RUN NOW, AGAINST THE SPEC — and most of the ten do not survive**

**Two measured facts decide most of it.**

**(a) There is NO time-series endpoint in the API.** Every `GET` returns current state or a keyset page of
discrete events. **(b) `rx_bytes`/`tx_bytes` carry this in the spec itself:**

> *"Raw gauge since the last handshake **(display only, never summed as monotonic)**."*

**The spec already forbids the rate charts.** "Site-Link Throughput" and the Overview area chart are not
merely unbacked — **they are drawn against a field whose own description says it cannot be drawn that way.**

| visualization | endpoint | verdict |
|---|---|---|
| peer / device **donut** (Overview) | `/nodes`, `/devices` | **KEEP** — proportion of current state |
| **verdict-timeline histogram** (Access Events) | `/access-events` — `occurred_at` + `decision` | **KEEP** — *discrete events binned*, not a sampled rate |
| **sync-freshness bars** (Groups) | `/idp-sync/{provider}/health` | **KEEP** |
| **network map** (Sites) | `/sites` + the existing `siteLinkGraph` | **KEEP** — force-directed **reduced to the deterministic hub-and-spoke the model already computes** |
| role pyramid + MFA donut (Users) | `/members` | **KEEP** — proportions |
| address-space heatmap (Routed Ranges) | `/routed-ranges`, `/site-subnets` | **KEEP** — occupancy of a space, genuinely faster than a table |
| radial device fabric (Devices) | `/devices` | **RE-EXAMINE at S14.4** — *what does it answer faster than a table?* |
| access-flow bipartite curves (Access) | `/policies` + `/groups` | **RE-EXAMINE** — likely answers less than the rule table |
| actor-swimlane stream (Audit Log) | `/audit-logs` | **RE-EXAMINE** — a log is already chronological |
| **fleet-risk bubble plot** (Gateways) | **none — Tier-3, not built** | **ROADMAP** |
| **Site-Link Throughput / area chart** | **none — and the spec forbids the field's use this way** | **ROADMAP** |

**The `gap` decision is the reason the histogram is honest.** `AccessEvent.decision` includes `gap` as a
first-class enum value, so **missing data renders as a gap rather than as zero.** A chart that draws absent
data as zero is the reassuring-empty defect with an axis on it.

## C3 — **ONE PRIMITIVE SET, and it is THREE, not ten**

Everything that survives is one of: **a proportion** (donut / stacked bar / pyramid), **a binned count over
discrete events** (histogram / freshness bars), or **a node-link graph** (network map). The heatmap is a
proportion on a grid.

## C4 — **THE BINDING, MADE MECHANICAL: a chart cannot compile without naming its source**

Prose ("names its endpoint or is marked roadmap") is a convention. **PROPOSED — a required prop:**

```ts
type VizSource = { endpoint: string } | { roadmap: true; why: string };
```

**A chart with no source does not typecheck.** `roadmap: true` renders a visible not-built state — never a
plausible drawing — and a test asserts **no `roadmap` chart ships without that marker.**

**And `Loaded<T>` binds every chart:** a failed load renders the retry, **never an empty axis**; zero data
renders "no data", **never a flat line at zero.** The measured pattern the founder named — *both known
render-floor violations are charts* — is exactly this failure mode, so the guard belongs on the primitive.

**DEMONSTRATION:** the peer donut on Dashboard (`/nodes`) and the verdict histogram on Access events
(`/access-events`) — one proportion, one binned-count, both with named endpoints, **in this slice**.

## B2 — TOASTS WITH UNDO · the criterion, as data

**`UNDOABLE_ACTIONS` — six actions, every one a STATE TOGGLE on an object that keeps its identity.**
`NOT_UNDOABLE` carries the exclusions **with their reasons**, so a future author must argue with a recorded

honoured.**

**THE THREE PROPERTIES, each asserted:**

1. **A real API call, audited as its own act** — never a client-side "put the row back".
2. **FAILURE IS LOUD** — a failed undo does not dismiss, says what did *not* happen, and offers a retry. A
   silent failure would leave the user believing they reversed something they did not: **strictly worse than
   the original mistake, because they have stopped worrying about it.**
3. **A toast is not a record** — it is announced (`role="status"`, `aria-live="polite"`), and the audit log is
   the record.

## B3 — THE MOTION GATE · `prefers-reduced-motion` **PROVEN TO REJECT**

**Two halves, and the CSS half is the one that protects code that forgets:**

- **CSS, UNCONDITIONAL** — `@media (prefers-reduced-motion: reduce)` re-points every `--tnx-duration-*` to
  `0ms` (shipped in slice 0). **A component that never checks still animates for zero milliseconds.**
- **JS, for what CSS cannot reach** — `motionAllowed(prefersReducedMotion)`, pure; the preference read **once**
  at the app edge by `MotionProvider`, which also listens for **mid-session changes** (turning the setting on
  while the app is open must take effect).

**FAILS TOWARDS LESS MOTION:** no `matchMedia`, a throwing `matchMedia`, or no provider all yield **reduced**.
The asymmetry is the reason — *not animating for someone who would have enjoyed it costs nothing; animating for
someone who cannot tolerate it makes a person feel ill.*

**The media-query literal is exported and asserted**, because a typo **fails OPEN**: `matchMedia` returns
`matches: false` for an unparseable query, which reads as "no preference".

## THE LIBRARY DECISION, AND IT WAS MEASURED

**HAND-ROLLED SVG. No charting library.** Of the ten named types a general library covers **at most three**
(donut, histogram, bar) and **none** of the force-directed map, the bipartite access-flow, the address-space
heatmap or the radial device fabric. **A library would be added for three and the other seven hand-rolled
anyway** — which is exactly how *"a design system acquires four charting libraries."*

## THREE PRIMITIVES, NOT TEN

`Donut` (proportion of a current-state total) · `Histogram` (binned count over **discrete events**) ·
`NodeLink` (topology). The heatmap is a proportion on a grid.

**`NodeLink` IS DELIBERATELY NOT FORCE-DIRECTED**, though the wireframe drew it that way. The model already
computes a deterministic hub-and-spoke (`siteLinkGraph`, S8.2), and **a force simulation over a known structure
produces a different picture on every render of the same data** — untestable, unmemorable, and impossible to
describe over a support call. **Determinism is worth more here than organic-looking placement.**

## `VizSource` — THE RENDER-FLOOR RULE, MOVED FROM PROSE INTO THE COMPILER

```ts
type VizSource = { endpoint: string; roadmap?: never } | { roadmap: true; why: string; endpoint?: never };
```

**PROVEN TO REJECT — four ways, all COMPILE ERRORS, not test failures:**

| omission | error |
|---|---|
| no `source` at all | `TS2741: Property 'source' is missing` |
| both `endpoint` **and** `roadmap` | `TS2322: Type 'boolean' is not assignable to type 'true'` |
| `roadmap` with no `why` | `TS2322: Type '{ roadmap: true; }' is not assignable to type 'VizSource'` |
| no `failed` | `TS2741: Property 'failed' is missing` |

**`endpoint` IS A CLAIM ABOUT A PERMITTED READING, NOT ABOUT A URL BEING REACHABLE** — which is the whole
point of the audit reading the spec's semantics. `rx_bytes`/`tx_bytes` is the instance that proves it: **the
endpoint exists, the field exists, and the field's own description forbids the use** (*"raw gauge since the
last handshake, display only, never summed as monotonic"*). An audit that only asks *"does an endpoint supply
this?"* answers **yes** and lets the throughput chart through.

## THE THREE HONESTY GUARDS, ON THE PRIMITIVE RATHER THAN PER SCREEN

1. **A FAILED LOAD DRAWS NOTHING** — never an empty axis, never a flat line at zero. *"No traffic"* and *"we
   could not read the traffic"* are opposite claims that **draw identically**.
2. **A GAP IS DRAWN AS A GAP.** `AccessEvent.decision` carries `gap` as a first-class enum value because the
   agent can know it did not observe a window. **A zero-height bar would make "no denials" and "we did not see"
   identical** — the reassuring-empty defect with an axis on it.
3. **A ROADMAP CHART RENDERS ITS HONEST STATE**, never a plausible drawing. **A greyed-out sample is still a
   picture.**

**And the numbers are TEXT, not only geometry.** An SVG arc is unreadable to a screen reader, unqueryable by
the tier, and ambiguous to anyone who cannot distinguish the colours — **three failures with one cause**, the
same one `Badge` avoids.
