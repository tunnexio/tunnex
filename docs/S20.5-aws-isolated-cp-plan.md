`caddy reverse-proxy --from https://cp.13.206.39.40.sslip.io --to nginx:8080`.

the admin API, so the first conversion requires a **brief Caddy-only restart**,
not a live reload. Later reloads require the enabled internal admin endpoint.
See [Caddy command behavior](https://caddyserver.com/docs/command-line).

Retain its exact existing image, `tunnex_default` network, 80/443 port mappings,
`tunnex_caddy_data:/data` and `tunnex_caddy_config:/config`. Its measured bridge
gateway is `172.18.0.1`. Recheck that address before using the candidate's
`172.18.0.1:18080:8080` publication. `127.0.0.1` inside Caddy is not the host;
do not attach candidate services to the old project's network to work around it.
Different bridge networks can communicate through published host ports; verify
that path before the edge change. No manual firewall repair is part of this
plan. See [Docker bridge networking](https://docs.docker.com/engine/network/drivers/bridge/).
