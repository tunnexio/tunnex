## The four proofs — 4/4 GREEN

### Proof 1 — B1: enforcing + grant → flow  (Slice-1 substitute → wire)
Device `openvpn` (10.99.0.11) homed on aws-gw-1 (hub-set), split-tunnel. Client routed both
sites via tun (`10/16`, `172.31` → utun).

| target | before grant | after `nykaa→azure-lan` (per-user rule) |
|---|---|---|
| `10.0.0.4` (behind-host, ttl 62 = 2 hops) | 100% loss | **0% loss** |
| `10.0.0.5` (azure-gw, ttl 63) | 100% loss | flows |
| `172.31.10.85` (aws-site, **not** granted) | — | **100% loss** (default-deny holds) |

The per-user grant reached the **OVPN /32**; the un-granted host staying dead proves the grant
flipped only its CIDR. Also proves WF-OVPN-7 (site routes pushed to the OVPN client) + OVPN-/32
cross-site transit. Grant path = **per-user rule** (`src_kind=user`), since group members are
users and a device inherits from its owner.

### Proof 2 — revoke → CRL → death (< 60s reneg bound)
Two independent severances, both on the wire:
- **conntrack-flush** (agent log `conntrack_flushed {flows:1}`) killed the in-flight ping
  instantly (seq 38→39) — the S8.7 flush firing for OVPN.
- **crl-verify reconnect rejection** (`/etc/tunnex/ovpn/ovpn.log`):
  ```
  VERIFY ERROR: depth=0, error=certificate revoked:
  CN=019f9774-02cb-707c-b885-7ebc9524be73, serial=265485057...
  Sent fatal SSL alert: certificate revoked
  ```

### Proof 3 — D-S9.5-4 reload-no-restart
`CRL: loaded 1 CRLs from file …/crl.pem` (re-read) with **openvpn PID 26 unchanged** across the
revoke. CRL rebuilt (crl.pem mtime advanced), process never restarted.

### Proof 4 — WF-OVPN-9 multi-remote failover
Fresh device `new-openvpn` (10.99.0.11), profile carried **2 remotes** in priority order
(`15.134.60.253` aws-gw-1, `15.135.130.96` aws-gw-2). CCD confirmed **warm on BOTH hubs**
pre-failover (Part B enabler, widenedOVPNRoster). Killed primary (`docker stop tunnex-node` on
aws-gw-1) → client failed over to aws-gw-2; server-side accept:
```
VERIFY OK: depth=0, CN=019f9792-0659-72ef-9d6f-63a01822ad16
Control Channel: TLSv1.3 … peer cert 2048-bit RSA (IV_PLAT=mac)
```
Ping resumed cross-site through the standby. Full HA hub **promote → demote → failback** cycle
rode along (hub set v17 → v18 → v19); failback self-healed in ~10s once aws-gw-1 re-synced.
