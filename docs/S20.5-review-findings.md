## Tier 1 — CRITICAL

### 1. Host-posture teardown leaves the D11a unrecoverable wedge

- **Severity / confidence:** CRITICAL / CONFIRMED (re-verified)
- **Evidence:** `apps/node/internal/hostposture/kernel_linux.go:459` (`return k.restoreSysctls(journal.Sysctls)` placed after `cleanupStagedWireGuard`), delete at `:557`, wedge read at `:308`; `apps/node/internal/hostposture/manager.go:189-195`
- **Impact / reachability:** Link *creation* is a four-phase journaled transaction; link *destruction* has no phases. `RestoreAndCleanup` deletes `wg0` and only afterwards calls `restoreSysctls`, which errors whenever a live readback disagrees. `net/ipv4/ip_forward` is routinely rewritten by kube-proxy and CNI plugins, so this is an ordinary non-crash outcome. On that error `journal.State = StateRestored` is never reached: the journal durably reads `committed` with a positive `IfIndex` while the kernel has no `wg0`. The next gateway scheduled onto the node enters `case WireGuardPhaseCommitted`, the readback is absent, and the manager blocks permanently. The gateway init container waits on a heartbeat that will never come, so the Pod stays Pending, so the owner count never drops, so the manager never re-enters the teardown branch. A process crash anywhere between the delete and the journal write produces the identical state. This is the exact shape box-walk Leg 0 says requires a provider-managed node reimage.
- **Existing coverage:** `manager_test.go:183` (`TestManagerCleanupFailureRemainsRetryableAndNeverClaimsRestored`) injects `restoreErr` on a `fakeKernel` whose entire `RestoreAndCleanup` is a stub, so it proves retryability only for an atomic cleanup failure — the one shape the real kernel cannot produce.
- **Disposition:** **FIX BEFORE WALK (item B).**
- **Type:** defect + test-evidence defect

### 33. Node image version fallback is a mutable `dev`

### 35. Preflight hook deletes its own failure diagnostic

### 36. One invalid anchor entry throws for every origin
MEDIUM / mechanism CONFIRMED, trigger PLAUSIBLE. `apps/client/src/main/enrollmentanchor.ts:154-157, 167-182`. `parseAnchorMap` throws on the first entry failing validation, including an entry for an unrelated origin. ### 37. Durable read requires write permission, so a locked file reads as corruption
MEDIUM / mechanism CONFIRMED, trigger frequency PLAUSIBLE. `apps/client/src/main/durablefile.ts:54-58, 128-141` (`O_RDWR` on the read path, deliberate for a Windows flush concern). A backup or antivirus agent holding the file with a deny-write share, or a read-only restore, throws a busy or permission error that is not ENOENT, which callers convert to their corrupt error. Temporarily unwritable and unrecoverably corrupt have opposite remedies. **HELD.** Type: defect.

### 38. Changing the server URL strands an anchor holding a private key

## Tier 4 — LOW

### 43. Lifecycle-claim endpoints have zero web call sites
LOW / CONFIRMED (absence question, answered from the specification). `openapi/openapi.yaml:1410-1690`. All eleven node-lifecycle-claim endpoints added by this story, including both abort verbs, have no caller under `apps/web/`. Every other Kubernetes mutating operation does, so this is the sole gap. It matters because purge refuses while a non-terminal claim exists, so a claim stranded by a dead installer host is blocking and nothing in the interface shows it exists, which node it belongs to, or that it is blocking. The decisions paper makes the CLI the entry point, which justifies no install button; it does not disposition the absence of visibility. **HELD — decide-item on product intent.** Type: decide-item.

### 44. Runtime images resolve by mutable tag by default

### 45. The held-operation refusal is untested and names a holder that does not exist

No test asserts this string; the three tests reaching this function all exercise the anchor-CAS-loser branch instead. **HELD.** Type: defect + test-evidence defect.

### 46. `purge-state` discards the lease renewal error on the success path
LOW / CONFIRMED. `apps/cli/internal/cli/k8s_lifecycle.go:2100-2113, 2135`. The deferred cleanup joins the renewal error only when the delete was not confirmed, so losing the mutual-exclusion fence during the destructive window is silent and the command exits zero. ## Proved negatives

Run and cleared, recorded so the coverage is legible:

- **CLI token hygiene.** The raw token exists in one function chain, reaches `kubectl` through stdin only, and the redaction matches the literal on-wire form because the manifest uses `stringData`. No `--set`, argv, environment variable or values file carries it. The error wrapper never echoes a response body.
- **CLI plan non-mutation.** Every mutating command site is enumerable and every one sits after the approval gate. The anchorless recovery path persists nothing; chart materialization writes only a private temporary directory.
- **Operator RBAC least privilege.** No wildcard API group, resource or verb, and no secrets, nodes, pods/exec or data-plane grant, in both the operator config and the chart. The contract test censuses by exact rule count rather than presence grep.
- **Client invariants.** No new generic preload passthrough; the four new surfaces carry only identifiers and booleans. No new client test imports Electron transitively.
- **Commit `33a0971f` is internally consistent.** The removed protocol's identifiers have zero remaining references and no persisted value encodes the removed state. The now-unreferenced `session.ts` is dead code and one comment is stale; both are reported here rather than as findings.
- **Migration 0132.** The five-way state check is consistent with every update in the query file, the guard trigger ordering holds, remint genuinely invalidates the prior secret, and epoch allocation cannot collide.
- **Enum alias reconciliation in `2dd50baa` is correct**; keeping the aliases would have been a duplicate declaration.
- **No provider-named chart branch exists.** Provider names appear only as CRD enum values with a pairing rule.

- **Wedge with no exit — six instances across four surfaces** (findings 1, 3, 14, 18, 36, and the strand half of 25). The largest class in this review, and it lands squarely on the crash-safety this story claims.
