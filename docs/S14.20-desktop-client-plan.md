# 1. WHAT THE WIREFRAME ACTUALLY SPECIFIES

**One window. One job.**

| surface | content |
|---|---|
| **Title** | `tunnex · hyperdrive` |
| **Status head** | status label · profile · assigned IP |
| **Connection stats** | current rate · **sparkline with a peak marker** (`2.2 KB/s peak`) · `BYTES IN ↓` · `BYTES OUT ↑` · `DURATION` · `PACKET RECEIVED` |
| **Primary verb** | `Connect · link the mesh` → `Cancel · linking peers…` → `Disconnect · tear down the mesh` → `tearing down tunnel…` |
| **Toggle** | Split tunnel |
| **Taxonomy** | ten states (below) |
| **Tray** | solid = connected (handshake fresh) · pulsing = connecting / re-keying · grey = disconnected · **red badge = revoked / kill-switch, and an OS notification fires** |

**Two rules stated in the block, and both are constraints rather than decoration:**

1. ⛔ **"Status is derived from handshake liveness — the icon is never green while the tunnel is dead."**
   Our `trayview.ts` already implements exactly this (`HANDSHAKE_STALE_SEC`); it is the one part of the
   client that is already right by design rather than by accident.
2. ⛔ **"MFA touches the client only via browser re-auth: expired credentials → 'Sign in with your browser'
   prompt, NEVER an in-app password field."** This is a **security constraint on the new UI**: the client
   must not grow a credential form. It is also why `EXPIRED CREDS` is a state and not an error.

**There is NO dashboard content in the block.** No device list, no gateway health, no audit, no settings
beyond split-tunnel and server URL. **The design already says the client is not a small dashboard.**

## The ten states vs. what we model

`TrayState` today: `disconnected · connecting · connected · failed · revoked · pending · migrate_retry ·
posture_blocked` — **8, of which 7 map to the design.**

| design state | ours | gap |
|---|---|---|
| CONNECTED · CONNECTING · DISCONNECTED · REVOKED · POSTURE_BLOCKED · MIGRATE_FAILED · AWAITING ADMIN APPROVAL | ✅ | — |
| **HELPER OUTDATED** | ❌ | the version handshake EXISTS (`helperclient.ts`, `helperinstall.ts`) and never reaches a state |
| **KILL-SWITCH ENGAGED** | ❌ | pf/WFP kill-switch ships and is wire-proven; the client has no state for "engaged" |
| **EXPIRED CREDS — RE-LOGIN** | ❌ | `expires_at` is already used for no-oracle 401s; the tray does not carry it |
| — | `failed` **(ours)** | a real state the design omits — **keep it**; see §0's law about the design and failure states |

> **All three gaps are the same shape: the FACT is already known in the client and no STATE carries it to
> the tray.** Plumbing, not protocol.

# 2. WHAT EXISTS TODAY — and what must not break

**33 main-process files / 3,238 lines · 1 preload / 51 lines · 12 test files / 1,818 lines · 3 scripts.**

## ⛔ THE PARTS WHERE A MESS COSTS THE MOST — do not touch in a UI migration

| area | why it is dangerous |
|---|---|
| **`preload/`** (51 lines) | the ONLY privileged surface. Verb-specific allowlist, **no generic `invoke`**, **no `getToken`** — the raw bearer never enters the renderer. Widening this is the single highest-risk edit in the app. |
| **`ipc.ts`** (449 lines) | the 8 verbs: `auth:login/logout/status · config:get/set · tunnel:up/down/status`. |
| **`helperclient.ts`** (219) | the privileged protocol: `connect · down · status · set_allowed_ips · set_gateway_peer · set_resolvers · posture_status · path_check · code_signing · tunnel_down`, plus the **version handshake** and **canonicalised caller auth**. |
| **`bundle.ts` + `csp.ts` + nav lock** | `app://` path resolution with escape rejection, per-response CSP, and a navigation lock that refuses any non-`app://` URL. This is the renderer's sandbox. |
| **`tunnel.ts` · `revocation.ts` · `healthmonitor.ts` · `approvalmonitor.ts` · `routedrangesmonitor.ts`** | app-level singletons (S6.4 root fix). The tunnel SURVIVES window close — that is the point of a tray. |
| **`quitguard.ts`** | quit continuity (S6.8). |
| **packaging** | `.pkg` universal + root `postinstall` (LaunchDaemon), NSIS `perMachine` + SCM service + wintun. `isRelocatable: false` pins `/Applications` because **caller-auth trusts a fixed path**. |

## The renderer — this is the makeshift

**The client's renderer IS the web SPA.** `electron-builder.yml` copies `../web/dist` → `Resources/web`;
`index.ts` loads `app://tunnex/index.html`. **There is no client-specific UI at all.**

**Seven web files branch on desktop:** `main.tsx · components/AppShell.tsx · components/DesktopSettings.tsx ·
components/TunnelControl.tsx · lib/desktop.ts · pages/Dashboard.tsx · pages/Login.tsx`.

**That is the coupling to remove**, and it is smaller than it looks: **two** components are genuinely
desktop-only (`DesktopSettings`, `TunnelControl`); the rest are `if (isDesktop())` branches inside shared
screens.

- **SIGNING: there is none.** `identity: null`, `CSC_IDENTITY_AUTO_DISCOVERY=false`. Ad-hoc only.

# 4. THE PLAN

## 4a · What the new client IS

**One window, four regions:** status head · connection stats · the primary verb · split-tunnel. Plus tray +
notifications. **Ten states.** Nothing else.

**What it must NOT contain:** device list · gateway health · sites · routed ranges · Kubernetes · access
policies · users · audit · org settings · the command palette · the nav sidebar · the top bar.

**Named for removal from the client's renderer:** `AppShell` (sidebar + topbar + nav), `Dashboard`, and every
`pages/*` route. The client will not mount the router at all.

## 4b · Shared vs. its own — matching Item A's ruling

| shared | its own |
|---|---|
| **design tokens** (`generated/tokens.css`, the palette) | **every component** |
| `lib/format` (relativeAge, bytes) | its own shell, its own status card, its own stats |
| `lib/desktop.ts` (the bridge type) | its own entry point + `index.html` |

**Tokens shared, components separate** — the founder's expectation, and it is the right line: a token change
should reach both, a layout change should not.

## 4c · MIGRATION ORDER — a working client at every step

| step | what | why it is safe |
|---|---|---|
| **1** | Add a SECOND vite entry in `apps/web` (`client.html` + `client.tsx`) that renders a placeholder. Build both. **Do not point Electron at it yet.** | zero runtime change; the current client keeps loading `index.html` |
| **2** | Build the connect surface + stats in the new entry, behind the existing bundle. Review it **in a browser** at `/client.html`. | **the whole UI is reviewable without Electron** |
| **3** | Flip `index.ts` to load `app://tunnex/client.html`. **One line, one revert.** | the only risky moment, and it is reversible in one commit |
| **4** | Add the three missing states (helper-outdated, kill-switch, expired-creds) to `trayview.ts` + `notifyview.ts` — **view-models first, tested** | pure functions, no privileged code |
| **5** | Remove the desktop branches from the seven web files | after the client no longer loads them |
| **6** | Drop `../web/dist` → keep only what the client entry emits | packaging change, verified by a pack run |

**Steps 1–2 are the bulk of the work and touch NO privileged code.** The helper, preload, IPC, packaging and
signing paths are untouched until step 6, which only narrows what is copied.

## 4d · WHAT BREAKS IF WE GET IT WRONG

| risk | consequence | guard |
|---|---|---|
| ⛔ **Widening the preload** | a compromised renderer gets a privileged verb. **The worst outcome in the app.** | preload is **out of scope** for every step; `security.test.ts` asserts no generic invoke |
| ⛔ **Breaking the helper version handshake** | client and helper disagree → tunnel up with a stale privileged binary | `helperclient.ts` untouched; the new state only READS the handshake |
| ⛔ **Changing the app path** | `isRelocatable: false` + caller-auth trust a fixed `/Applications` path | packaging config untouched until step 6, and that step changes only `extraResources` |
| ⛔ **Kill-switch regression** | fail-closed becomes fail-open — this is wire-proven behaviour and the most expensive thing to break | no helper or tunnel code in any step; the kill-switch STATE is display-only |
| **Taxonomy drift** | tray green while the tunnel is dead | `trayview.ts` already derives from handshake liveness; new states extend the union and the exhaustive `switch` fails to compile if one is unhandled |
| **Losing the app:// sandbox** | renderer escapes to the network | `bundle.ts`/`csp.ts` untouched; only the FILE the loader points at changes |

## 4e · HOW YOU REVIEW EACH STEP

- **Steps 1–2 — in a browser.** `http://localhost/client.html`. **This is the important one:** the entire new
  UI, all ten states via a `?state=` preview, no Electron needed.
- **Step 3 — Electron, once.** `pnpm --filter @tunnex/client build && pnpm --filter @tunnex/client start`.
  Check the window loads the new surface and the tray still works.
- **Step 4 — unit tests + the state preview.** The view-models are real proof; the tray WIRING is not.
- **Steps 5–6 — the web app and a pack run.** `bash scripts/pack.sh mac` and install the `.pkg`.

## ⛔ 4f · WHAT I WILL NOT CLAIM

**Main-process wiring is a NAMED GAP and stays one.** Client tests import no Electron at runtime, and the
artifact grep cannot reach the main process — it is a separate build from the web bundle. So:

> **Tray icon selection, notification dispatch and IPC round-trips are proven by VIEW-MODEL TESTS ONLY.
> Whether the icon is actually set is unverified by any instrument we own.**

Of the ten states, **6 are reachable on a local stack** (connected/connecting/disconnected/revoked, plus
pending and posture-blocked on enterprise). **4 are not** without contrivance — migrate-failed,
helper-outdated, kill-switch-engaged, expired-creds. The `?state=` preview proves the RENDER, never the
TRANSITION, and will say so on screen.
