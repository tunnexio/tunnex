# Worker and scoped skill configuration decisions

Dependency-ready worker wiring must remain dormant without both a runtime provider and qualified network coordinator. Startup scan, bounded serial batches, explicit wake-up, cancellation and retry are ordinary backend behavior; a successful worker construction is not qualification. No environment-variable Boolean may substitute for network isolation evidence. Composition root supplies no qualified adapters in this slice.

Skill selection is proposed as approved immutable instructions-only revisions for the first slice. Exact skill names/catalog are not user-specified and none are seeded. Catalog revisions belong to one organization; a template explicitly allows each revision. User selection cannot broaden requested network scope. Configuration supports bounded enumerated choices and Booleans only, no secret/free-text/script/package/host-path input. Do not store runtime keys or secret values in create intent or instruction text.

Validate canonical selection before create intent hashing; reject duplicates, unknown/disallowed/disabled revisions, unsupported config keys/types/choices and missing required fields. Selected revision/configuration is immutable with sandbox create intent. Optional skill network requirements must fit inside both requested scope and template cap, which remain bounded by current creator access. A skill never adds policy rules or uses the creator credential. Resume revalidates selected revisions and current caps.

Catalogue persistence and browser selection are control-plane configuration, not successful materialization. Immutable instruction digest verification and unprivileged workspace materialization need an actual qualified runtime; the existing Skills availability flag remains false until that adapter exists. Package installation, arbitrary executable skills, write-only secret references and hosted-agent/MCP integrations are later phases. Approved instructions are trusted authored content, not a mechanism to run arbitrary installation commands.
