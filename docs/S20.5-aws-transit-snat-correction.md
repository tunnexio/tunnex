# S20.5 AWS WireGuard transit SNAT correction

## Evidence and scope

The API lock correction restored fresh HA leases. Live edge conntrack still
records client `10.99.0.2` traffic to Service VIP `100.96.0.3:8080` translated to
edge host address `10.240.10.204`. The connector has no corresponding flow.
The existing AWS destination-tunnel exemption protects returns, not transit.
See `walk-artifacts/S20.5/aws-20260905/api-lock-retest.md`.

This is an essential correction authorized by the user's parallel-fix approval.
It does not authorize wider networking grants, default CNI changes, or a merge.

## Decisions (implementation contract)

1. Preserve the existing destination-tunnel return. Add one distinct owned AWS
   return matching canonical current IPv4 tunnel **source**, ingress `wg0`, and
   egress `wg0`. The marker is `tunnex_k8s_aws_snat_transit_bypass`.
   This exempts only WireGuard-to-WireGuard transit from AWS source NAT. It does
   not grant forwarding; default-deny policy and WireGuard peer identity remain
   separate mandatory boundaries. Native Pod/host internet egress is unchanged.
2. Reject blanket source/RFC1918/CGNAT exemptions. Reject deriving VIP ownership
   from arbitrary routes. A VIP inventory extension would require explicit
   trusted destination provenance on edge nodes, which do not have connector
   VIP mappings; it is unnecessary for this packet-mechanism correction.
3. Use journal schema 4 and a new closed scope `ip_masq_and_aws_transit`.
   Schema 3 remains byte-compatible and grants destination-only AWS authority;
   schemas 1/2 remain IP-MASQ-only. Never expand an active historical receipt in
   place. New epochs receive schema 4. Old managers fail closed on schema 4;
   cleanup by a capable manager is required before downgrade.
4. Schema 4's fixed AWS receipt names both markers. Readback must prove exact
   source, ingress, egress, verdict, namespace and marker. Schema-3 operations
   must never create/delete the transit marker. Historical cleanup may refuse
   unexpected newer artifacts rather than borrow future authority. Baseline
   census recognizes both markers and refuses leftover owned artifacts.
5. Keep lock, heartbeat freshness, two advancing authority observations,
   durable-before-write and cleanup serialization unchanged. Cleanup handles
   partial insertion and duplicates without requiring foreign topology ready.
   Existing KUBE-before-AWS and exact foreign AWS grammar checks remain intact.
6. Deploy through product lifecycle paths with honest Helm provenance. Upgrading
   the binary alone does not migrate an active schema-3 epoch. Establish a new
   epoch through normal owner removal/cleanup and lifecycle installation; do
   not edit journals, Secrets, PVCs, rules, or Helm history. Any inability to do
   this through the product is a lifecycle blocker, not permission to patch it.
7. Candidate packaging currently orders prereleases by a hash-derived token,
   so a later commit can compare as an older manager version. Add an optional
   explicit canonical positive walk sequence (1 through 999) yielding
   `0.0.1-walk.<sequence>.sha<actual 32-hex HEAD prefix>`. Preserve the historical
   version when omitted, keep the 50-character bound and full-SHA manifest,
   and reject arbitrary version overrides. This is an honest new private
   candidate, not a published product release or rewritten old chart. All
   component builds must use the same selected candidate version.

## Required proof

- Exact native and iptables-nft-save roundtrip for both owned rule shapes;
  malformed ingress, source, marker, verdict and namespace fail closed.
- Old schemas retain their receipts/scopes; new scope cannot come from schema 3.
  Cleanup/crash/duplicate/partial-write and authority-expiry tests.
- Linux packet proof with fresh five-tuples: WG transit preserves client IP;
  non-WG ingress and ordinary egress still undergo expected AWS SNAT; foreign
  rules survive reconciliation and withdrawal. Existing conntrack bindings are
  not evidence for newly installed NAT rules and must not be broadly flushed.
- Independent review, node/host-posture tests, then native AWS deployment and
  sustained local IP/FQDN access plus denied-flow proof before HA fault testing.
- This paper and unit tests do not mark a live walk leg complete. NLB remains
  explicitly skipped. Exact final component provenance and CI remain required.
