# S2S-2 — Pure runtime evidence qualification

Status: local implementation slice, 2026-09-24. This narrows the proposed runtime plan's pure-test step to an engine-neutral, non-persistent evidence evaluator. It does not select strongSwan, allocate kernel identifiers, deliver secrets, choose an outbound tunnel, acknowledge cleanup or connect to the production reconcile loop. Those runtime-plan decisions remain open. No dependency, schema, daemon, host or UI changes.

## Contract

Add `apps/node/internal/ipsec/evidence.go`: a deterministic, side-effect-free function over expected assignment, normalized observation, caller clock and positive finite freshness budget. Return per-tunnel candidate evidence with fixed refusal reasons; never report connected, qualified runtime capability, activation authorization or cleanup success. Even an all-candidate result is only one prerequisite for future runtime orchestration.

Expected identity binds organization, assigned gateway, connection, exactly two distinct tunnel identities/slots, positive desired/configuration/secret revisions and policy revision. Ownership is supplied by the future allocator/adapter, never invented here: exact namespace, interface name/index/XFRM ID and a nonempty set of canonical IPv4 route tuples (destination, table, protocol, metric, output interface, gateway if used). Validate malformed/empty/duplicate identities and route entries; both tunnels need distinct interfaces and XFRM IDs. Do not choose routing constants or failover timing.

Observation must have a complete consistent inventory with a nonempty collection identifier, nonzero collection time, no future timestamp and age within the explicit budget. Bind each tunnel observation to the exact expected assignment and revisions and collection identifier; refuse missing, duplicate and extra observations. Kernel/daemon adapters are not part of this slice: normalized booleans are adapter assertions, not actual kernel readback proof.

Global evidence must carry its own exact assignment/revision binding, independently of each tunnel, and affirm daemon identity and exhaustive ownership inventory without collisions, plus refusal for forwarded and host-originated protected traffic including established flows. Per-tunnel evidence must affirm exact interface/route ownership, current CHILD_SA identity/revision, enforced policy revision, anti-spoof protection and underlay separation. Failure of any global check refuses both candidates. A tunnel-specific missing SA or mismatched object refuses that tunnel; another fully evidenced tunnel can remain a candidate. No path selection occurs. Rekey overlap or incomplete SA enumeration is refused conservatively; support requires a later adapter contract.

Inputs and outputs contain no PSKs, ciphertext, provider payloads or arbitrary diagnostic text. Do not serialize or persist observations; use closed reason codes. Do not mutate caller-owned slices/maps. Zero values refuse. The freshness budget and clock are trusted caller inputs: no production timing default is introduced here.

## Acceptance and limits

Write failing tests before implementation; cover each binding/revision, each refusal/enforcement flag, route tuple changes, duplicate/missing/extra objects, empty expected routes, negative/zero budget, missing/future/stale times and exact age boundary. Verify a healthy pair, only-one-candidate case, input immutability and inability of the result to change capability0. Independent adversarial review and focused race tests; compile the Linux node. No database required. This is deterministic logic proof only, not daemon, namespace, packet, provider or end-to-end traffic proof.
