# Readiness integration decisions

Consume the node service's existing finalized `PolicyHealthForNodes` computation, never rebuild a parallel sandbox policy hash. Conservatively require every active gateway in the sandbox organization (bounded100) because both inbound user and outbound destination paths may traverse another gateway. An empty/oversized gateway set or missing bound gateway fails closed. Each required gateway needs current known nonempty pushed hash equal to applied hash, no degraded health, and a server-stamped policy report newer than the existing node freshness window (future reports fail). This remains closed in a composition that cannot supply canonical hashes.

Trusted runtime/network/workspace/private SSH inputs must bind exact org/sandbox/peer/generation/runtime/image/spec; network setup must remain quarantined until qualified default-deny host/sibling/metadata/underlay controls are proven. Positive readiness additionally needs persisted pinned SSH identity, current admission and generation fence. Browser/runtime status bodies cannot produce receipts. Production network coordinator stays absent until isolated Linux packet-path qualification passes. Source implementations/tests of these gates are not packet-path proof.
