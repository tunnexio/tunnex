# Sandbox administration, decisions before code

The restored trial leaves organization opt-in/template off and the qualified worker absent. A generic ask-administrator message is unhelpful to an administrator, and no API currently manages these switches. Implement authoritative setup status with machine-readable creation blockers, role-specific CTA, admin read/write organization opt-in and quotas and publication management for existing profiles. Do not provision images, workers, peers, secrets or accounts through these endpoints. Image/metadata worker owns profile definitions, with Ubuntu/Minimal/Python/Node choices gated by actual support.

Status is readable by authorized human sandbox viewers; only sandbox:admin can read unpublished catalog/manage organization settings, sandbox:template_manage controls catalog publication. Existing DB membership authorization is rechecked in every store transaction. Source-only work; no live enablement or deployment. Org activation additionally requires current trusted provisioning readiness, enforcing mode, valid runtime org/deadline and at least one enabled runtime-compatible profile. Admin identity never supplies qualification or bypasses creator binding. Publication is distinct from qualification; disabled runtime can still manage catalog/quotas and remain blocked. Request carries expected settings/current publication value, preventing lost updates. Audit records are transactional. Disable/republish never widens stored image/resource/network caps; no new image profile is fabricated.

UI setup shows actual switches, quotas, runtime-ready boolean, policy mode and publication/compatibility of every existing profile. If readiness is false, activation is disabled with a concrete operator setup explanation and no fake enable button. Public/member inventory reasons and permissions come from server; older server fallback says availability details are unavailable rather than assuming an administrator can fix it. Lifecycle stop/delete remain independent of creation availability. Skills remain selectable/configurable within existing published-template eligibility.

Acceptance: admin/viewer/machine/cross-org route and store tests; no runtime activation with readiness false, expired or wrong-org binding, missing qualified catalog or non-enforcing policy; publication CAS/audit and settings CAS/ranges; accurate quota/creator blockers; UI admin CTA/member guidance/setup-disabled/error/save/catalog coverage. Go/vet/build and UI type/tests/build; no live writes. Subsequent activation requires separate concrete reviewed worker/profile/gateway/public SSH and resource/latency plan. Catalog publication does not assert image measurement/qualification.
