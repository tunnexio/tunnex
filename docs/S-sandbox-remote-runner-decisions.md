# Remote runner: initial source slice

Baseline: parent-confirmed integration base 9b5d17d, story/sandbox-foundation; branch story/sandbox-remote-runner. Initially inspected main b36ec15 had no sandbox foundation; branch was rebased onto the confirmed integration base before validation. This slice creates independent internal transport/lease primitives and does not change keys or delegation files.

Ownership: remote transport, operator-bound runner enrollment, capacity, local offline expiry. Account public-key APIs/UI and generated files belong to the separate keys worker. Human-only sandbox HTTP gate remains unchanged. No public OpenAPI routes, generated files or database migrations in this slice. Agent delegation is a separate story.

Locked architecture: one external runner initiates authenticated HTTPS polls to CP. An operator installs a CA and certificates with exact URI identities; enrollment is an immutable operator binding, not a browser-supplied identity. Both sides require TLS1.3 and verified peer chains. Kernel UID RPC stays local. CP holds only bounded pending control messages and never runs fallback workloads. Runtime helper and dedicated gateway stay runner-local; payload execution paths and user SSH stay off CP.

Protocol contract: POST /internal/sandbox-runners/v1/poll returns one request (or 204); POST /internal/sandbox-runners/v1/reply returns 204 for matching request ID. Each request has a stable UUID, bounded opaque JSON payload and deadline. Queue capacity is one in this initial implementation. A delivered pending request retains the same ID across reconnect/re-poll; the runner must durably deduplicate effects. Caller timeout removes authority to complete the call. mTLS identity is exact runner URI; no identity headers or UID-over-network authorization.

Offline lease contract: durable immutable sandbox identity/generation/expiry; lifetime <=900 seconds. After expiry, local callback fences/stops execution without waiting for CP. Preserve assets and cleanup receipts for canonical withdrawal/reconciliation; never claim peer withdrawal or release an address while offline. Persist receipt before considering expiry complete. Callback must be idempotent after crash.

Initial slice acceptance: authenticated queue/reply roundtrip; wrong/absent peer rejection; bounded queue; stable redelivery ID; cancellation; immutable expiry and crash/retry local receipt tests. Both Go editions compile/test. These are local substitutes, not remote wire acceptance.

Deferred integration: API configuration selecting remote transport exclusively, runtime-worker polling loop and durable command effect deduplication, certificate enrollment/revocation tooling, node/gateway enrollment, local expiry callback wired to exact provider identity, quotas/CPU/IO/log bounds, health/capacity UI and remote failure acceptance. No provisioning until the integrated source is ready. No paid-plan upgrade, broader policies or live mutation in this slice.

## Runtime wiring slice

Own additional seams: sandboxes/remote_worker.go and its tests, APIWorkerConfig.Remote, WorkerRPCClient close hook/expired-start guard, cmd/server private remote listener setup/health timeout, cmd/tunnex-sandbox-runtime remote config and supervision, and new offline enrollment command. No router/store/migration/generated overlap. Remote configuration is mutually exclusive with Socket/WorkerUID; only persistent exact-bound profiles are supported. API listener must bind a private IP and presents operator-installed TLS certificates. Runner holds only its client certificate, gateway/bootstrap material and local workload roots.

Enrollment is an offline operator command writing new mode0700 directory and mode0600 files; one pair of directional certificates, exact URI identities, DNS server verification, 24h expiry, CA private key discarded. Revocation/rotation replaces this single-runner CA and configuration; automated renewal remains deferred. No certificates generated or installed live in source validation.

Runtime supervisor persists a <=900s lease before granting execution, serializes effects and expiry, and retries failed offline fencing every second. Provider execution callbacks have <=25s deadlines, so fencing can wait for that bounded in-flight operation. Fence removes the sandbox's exact local network interface when present and stops its exact provider identity. Assets, canonical desired state, withdrawal ACK and address allocation remain untouched until CP reconciliation. The local UID RPC path remains unchanged; remote mode does not create its socket. Queue capacity remains one rather than the initial proposal's four while current admission is one slot.

## Integration boundary requiring disposition before live activation

Current empty-outbound creation requires terminal device.node_id == runtime GatewayID (store.go:245). Current historical reservation validation also pins the existing operational gateway and known terminal UUIDs (dev_reservation.go:43). A new runner-local gateway cannot silently reuse that binding. Preserve current Mac/gateway/reservation; choose explicit additional terminal enrollment on the runner gateway or a separately designed cross-gateway terminal path. The reservation must remain excluded from new runner authority while canonical historical proof stays pending. Do not weaken these checks or transfer owner/terminal identity under the EC2 approval. Coordinate these seams through parent before provisioning.

Absolute expiry ends runtime authorization; activation effects also receive context deadline at that expiry. Supervisor stops/fences locally as soon as the serialized bounded in-flight effect returns, not an instant wall-clock kill guarantee. Offline revocation cannot be learned before reconnection; no immediate SSH revocation claim. Canonical cleanup receipts follow CP reconciliation only.

## Bounded certificate lifecycle

Supersedes the initial no-renewal enrollment choice. Offline enrollment now creates a365-day CA whose key is installed ONLY on CP; endpoint leaves remain24h. The one-pair scoped issuer renews controller certificate presentation and authenticates runner renewal with currently valid mTLS identity, same existing public key and exact URI. Runner renews below12h remaining, persists only its new public certificate for restart, and continues local absolute-expiry fencing while CP is unreachable. Issuance is cached/rate-bounded to once/hour. Operator remote-config Revoked denies polling, replies, renewal and API control calls; activation remains unavailable. It does not claim immediate offline SSH revocation. Root rotation or offline loss exceeding valid certificate life requires explicit operator recovery, never a TLS bypass or human-cookie fallback. No broader certificate API/platform is introduced.

## Source integration and skill delivery bounds

Saved public-key and explicit owned-machine delegation slices are integrated on this isolated branch. Migration0181 uses a separate immutable remote terminal route record; it preserves existing local-terminal proof and the historical launch gateway. Current execution placement can be a new runner only under explicit private terminal/runtime endpoints, exact existing terminal identity and no organization-wide cross-gateway opt-in. Both gateways, including site-less ones, use the same active route projection for served desired state and canonical policy convergence. Explicit delegation sweeps and all source worker eligibility predicates remain intact.

Remote payload ceiling is now1MiB, matching the preexisting worker RPC limit. The initial64KiB ceiling rejected valid maximum selections:16 immutable skills with up to32KiB instructions each plus configuration and base64 JSON framing. Matching the existing limit avoids a separate upload/chunk service, admits existing valid skill choices and keeps one pending command, bounded30second effects,32 replay records and absolute900second leases. Skills stay inert workspace files, not host-side shell/install input. The current gateway still forwards terminal/file traffic; execution and workspace IO move off CP.
