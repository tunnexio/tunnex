# Lifecycle ACK locality, source decision 2026-10-03

Observed problem: the native local SSH flow worked while a terminated secondary instance retained an active Tunnex node row. All-active-org gateway ACK blocked Ready and final cleanup. Retirement requires handling two homed devices and is an unrelated live administrative action; no such action is authorized by this source fix.

Implement a new immutable nullable `local_terminal_gateway_id`, set only by bounded operator admission for empty outbound scope and an exact same-gateway human terminal device. A database constraint requires the terminal pin and empty scope. Compiler-owned local terminal rules are placed only on that pinned gateway; terminal or sandbox gateway changes withdraw them rather than moving grants elsewhere. There is no remote enforcement recipient, even when site prefixes overlap or remote topology is degraded. Existing records default NULL and retain all-active ACK behavior; do not retrofit the expired pilot's historical proof or release its reserved address.

For new records carrying this invariant, readiness and cleanup consume the existing canonical finalized policy hash/report of the exact pinned gateway. Unknown/mismatched hashes, stale/future/missing reports, refused policy versions and policy apply errors still fail. Remote site reachability health may be disregarded only for this local, no-outbound flow, after actual private SSH/network gates still prove readiness. Other health errors, legacy/unpinned/outbound records and wrong org/gateway are rejected or retain the conservative all-node gate.

Acceptance: compiler local rule appears only on pinned gateway and disappears after terminal/peer move; unrelated stale gateway is never labeled gone; primary stale/mismatch/apply error still blocks; legacy remains all-node; immutable SQL constraints prevent widening; readiness/cleanup call the scoped helper with exact target identity; migration downgrade refuses unfinished local records. Test with disposable PostgreSQL and pure compiler fixtures. No live migration, another sandbox, gateway record edit or forced Ready/Deleted is part of this implementation.
