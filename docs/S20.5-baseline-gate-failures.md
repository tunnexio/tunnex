## P1 — unordered runtime credential promotion

**Observed gate:** open-edition `TestRuntimeServicePostgresContract` failed at
`apps/api/internal/agentruntime/service_integration_test.go:244` when promoting
a candidate credential. The PostgreSQL log at `2026-09-05 09:10:57.541 UTC`,
backend PID 5586, identifies `AuthenticateAgentRuntimeCredential` and SQLSTATE
23505 for `agent_runtime_credentials_one_current_key`.

**Mechanism:** `apps/api/db/queries/agent_bootstrap.sql:145` uses one unordered
multi-row UPDATE to promote the candidate and supersede the current credential.
Migration 0094 creates an immediate partial unique index allowing only one
`state='current'` row per device. Candidate-first visitation attempts to create
a second current row before removing the existing one. The service maps the
database error to `ErrUnauthorized`; this is a fail-closed availability defect,
not evidence of an authentication bypass.

**Deterministic substitute:** the exact authored query body was executed against
equivalent relevant temporary columns/indexes with a verified sequential scan.
Application triggers and foreign keys were unnecessary for this reproduction.

| Same logical credential state; physical insertion order differs | Result |
|---|---|
| Current revision 1, then candidate revision 2 | Promotion succeeds |
| Candidate revision 2, then current revision 1 | 23505, `agent_runtime_credentials_one_current_key`, schema `pg_temp_3` |

Savepoint rollback preserved the original current and candidate states; final
ROLLBACK removed the temporary fixture. The original test's physical plan was
not captured. This substitute proves a valid visitation order fails, while the
original server log independently confirms the same unique-index failure.

**Recommended repair contract — not yet dispositioned:** explicitly order
demotion and promotion with appropriate per-device serialization, retaining
transactional atomicity, credential binding, uniform refusal, idempotent retry,
and concurrent authentication/rotation/revocation invariants. Re-earn review
with both physical-order witnesses and actual concurrency tests, then rerun
both complete API editions. Do not weaken the unique index, suppress the test,
or rely on a lucky query plan. The precise implementation needs a paper-first
disposition because it changes a production runtime-auth transition outside
the Kubernetes lifecycle repair.

## P2 — persistent bootstrap fixture collides on a constant hash

**Observed gate:** the independent enterprise run passed runtime tests, but
`TestManagedAgentBootstrapIsHashedSingleUseAndClientKeyed` failed at
`apps/api/internal/devices/agent_bootstrap_integration_test.go:75` with 23505
for `agent_bootstrap_tokens_hash_key`.

**Mechanism:** the expired-token fixture at lines 72–75 hashes a fixed literal.
The global uniqueness constraint comes from migration 0090. Fixture cleanup at
line 275 discards the error returned by `DELETE FROM organizations`. When the
organization has an audit row, its audit-log foreign key's `ON DELETE SET NULL`
attempts an UPDATE that the append-only audit trigger rejects. The transaction
rolls back, leaving the organization and its fixed token hash for another run.

**Direct evidence:** backend PID 6857 logs the duplicate-token failure at
`09:14:53.051 UTC`, followed by its own rejected organization cleanup at
`09:14:53.053 UTC`. The latter includes `audit_logs is append-only: UPDATE is
not permitted` and the FK's `SET org_id = NULL` statement. Read-only inspection
also found an earlier expired-token fixture alongside its `device.created`
audit row. Its fixture timestamps place insertion at `08:49:09.031908 UTC`; a
matching cleanup rejection appears at `08:49:09.033 UTC`. That older log omits
bound organization parameters, so attribution to the earlier exact fixture is
supported by timing and persisted-row evidence, not a logged parameter value.

**Recommended repair contract — not yet dispositioned:** make fixture values
unique per run and provide explicit, auditable test isolation that reports
cleanup failures without weakening production audit immutability. A unique
literal alone does not correct ignored cleanup failure. Do not delete the
existing fixtures, bypass audit triggers, or change retention permissions to
obtain green. The broader production organization-deletion/audit interaction
is not silently redesigned as part of a test-isolation repair.
