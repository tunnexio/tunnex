# User-owned custom skills

Explicit requirement: users must add their own skills through the UI, not only select an administrator catalog. This extends S08 and does not replace the ongoing lifecycle/runtime work.

No repository-specific skill document convention was found. Proposed lightweight MVP: a UTF-8 SKILL.md document, at most32KiB, with an opening/closing `---` block containing exactly `name` and `description`, followed by Markdown instructions. Name is a lowercase hyphenated slug up to64characters; description up to256characters. Accept plain or double-quoted scalar metadata, reject arbitrary YAML/aliases/multiline configuration/unknown front-matter keys. No new parser dependency is needed. Paste or import one .md file; imported content is untrusted plain text and rendered without executable HTML.

Custom skill records are organization/creator bound, private to their owning current member by default, with no admin/other-member content listing or sharing endpoint. Use current verified human sandbox:manage for writes and ownership for reads/edits/deletes; no caller owner/org attribution fields. Create is idempotent; edit is generation CAS and creates an immutable revision. Sandboxes retain the selected exact revision on edit. Delete is a tombstone that disables all revisions, removes them from selection and withdraws enrollment/runtime/policy eligibility; no silent replacement. Default bounds are20 active custom skills per user,500 per organization and20 revisions per skill, proposed implementation limits rather than user-specified values.

Users may select their own active custom instructions on an enabled runtime template without admin approval of the instruction text. This exception cannot install tools or alter template/runtime permissions. Other users' private revisions remain ineligible even if a template association is forged. Custom revisions carry empty network requirements and no secret/config/package/install fields in this first version. Their actual execution, if a user's local agent interprets them, is limited to the existing unprivileged sandbox environment/policy. The control plane only validates/stores/prepares inert content; it never executes imported installation instructions. Materials and availability remain gated until qualified workspace delivery exists.

UI provides Add custom skill, file/paste input, current private skill view, versioned save and delete; creation controls distinguish owner-private instructions from curated catalog entries. Existing template/Skills UI remains. Catalog metadata excludes other users' private entries and instruction bodies. User-owned source storage is independent of runtime qualification; creation/Ready gate stays closed.
