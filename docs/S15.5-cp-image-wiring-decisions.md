# S15.5 decisions: CP gateway image wiring

## D1 — locked: the API receives the verified node-agent image

The CP API service must receive `TUNNEX_NODE_AGENT_IMAGE` from the deployment
environment. The enrollment command uses this value, so omitting it makes a
fresh gateway fall back to the mutable `:latest` image even when the release
manifest is digest-pinned.

## D2 — locked: release provenance remains authoritative

The compose file and release manifest remain release-owned. Operators must not
patch compose files in place to make enrollment work; the signed release must
contain this wiring so the upgrade provenance hash stays valid.

## D3 — locked: no gateway re-enrollment is required

This is a control-plane configuration fix. Existing gateway state volumes and
identities are preserved; only a normal signed CP upgrade is required.
