# Durable start and readiness decisions

Concrete network adapter direction for the next implementation: keep the workload's provider-created network=none namespace, with only loopback plus a WireGuard interface and overlay routes. Create the WireGuard interface in a separate trusted control/birth namespace, then move the interface into the exact provider runtime namespace; its encrypted UDP socket remains in the birth namespace. This is the [documented WireGuard namespace mechanism](https://www.wireguard.com/netns/), not an AppArmor/tool-renaming workaround. Workload retains cap-drop=ALL/no-new-privileges and never receives bootstrap/runtime control credentials, host interfaces or sockets. Host routes/firewall/AppArmor remain unchanged. Before code/application, define a narrow node-side helper protocol that binds operation/runtime/spec/generation and pins namespace FDs to prevent PID reuse; reject preexisting/foreign links, routes, namespaces or uncertain ownership. API stays control-plane-only and must not call wgctrl directly. The exact Linux/user-namespace capabilities and source/binary/image compatibility must be verified on isolated fixtures before proposing the privileged setup. No shared-underlay sidecar, broad privileged workload, unqualified sudo service or host-network join is accepted as a shortcut. DNS requests, if future full-tunnel support admits them, must be preserved rather than silently stripped.

Clear handoff ciphertext once bound peer plus trusted local handoff are confirmed; lost local handoff requires cleanup/recovery, not another enrollment.
