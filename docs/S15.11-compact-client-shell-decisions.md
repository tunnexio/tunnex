# S15.11 - Compact desktop client shell decisions

## Scope

Make the managed desktop client feel like a compact VPN application rather
than a dashboard: one connection view, concise settings, and a fixed window
that does not leave a large text-heavy surface around the primary action.

## Evidence at entry

- The Electron window is a fixed 440 x 820 px surface in
  `apps/client/src/main/index.ts`.
- The existing client renderer mounts long routing, profile, and update copy in
  Settings, including raw main-process errors; the supplied comparison shows a
  compact VPN client with one connection card and a single primary verb.
- The x86 installer change is already isolated in PR #124; this story must not
  modify packaging or release assets.

## Decisions

### D1 - Compact shell: locked

The fixed desktop window remains 440 px wide and becomes 640 px high. The
Connection pane remains a single primary surface: status, concise live facts,
and one connect/disconnect verb. It must not become a second dashboard.

### D2 - Information density: locked

Settings retains every user-operable control, but long explanatory prose is
replaced with short, state-specific hints. The underlying security semantics
remain explicit: an imported profile states that posture and revocation
monitoring are unavailable; unsigned builds state that updates are manual.

### D3 - Error presentation: locked

Renderer-visible failures are mapped to a short, actionable client message.
Raw IPC and HTTP implementation strings, such as `revoke_device_failed: 409`,
must stay in logs rather than becoming product copy.

### D4 - Scope boundary: locked

No tray icon, VPN routing, enrollment, posture, updater, or installer behavior
changes in this story. Those existing flows are preserved; only their compact
client presentation is changed.

## Acceptance checks

1. The Electron window uses the compact fixed dimensions.
2. Connection and Settings remain reachable, with all existing actions intact.
3. The Settings pane has no raw IPC or HTTP error string exposed to the user.
4. Client renderer tests prove the concise error mapping and retained controls.
5. A local browser-rendered client preview is reviewed before the branch is
   pushed; native Electron packaging remains CI proof.
