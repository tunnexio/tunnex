# S15.6 — Managed desktop logout preserves device identity

Status: locked design (client implementation follows)

## Problem

The managed desktop client's normal sign-out currently calls the device-revoke
flow and deletes the locally stored tunnel configuration. The next sign-in
therefore mints a new device, a new address and, when approval is enabled, a new
pending approval. Sign-out is a session action, not a device-lifecycle action.

## Decisions

### D1 — Normal sign-out ends only the authenticated session (locked)

Normal sign-out brings the tunnel down, stops monitors, deletes the API session
credential and returns the UI to signed-out state. It does not revoke the device
or delete the encrypted local tunnel configuration.

### D2 — Reuse is server-validated before a tunnel can be armed (locked)

After sign-in, the client may reuse a stored configuration only when the API
confirms that its device UUID belongs to the newly authenticated user in the
selected organization and remains active. A pending device stays pending and
waits for approval; revoked, deleted, inaccessible or owner-mismatched devices
are never armed or silently revoked by the new session.

### D3 — Device UUID plus credential is the installation identity (locked)

The keychain-held device UUID and WireGuard credential identify an installation.
Hostname and MAC address are display/audit signals only: both can change or be
spoofed and neither can safely authorize a machine.

### D4 — Explicit removal is the only destructive device action (locked)

The client exposes a separate, clearly named "Remove this device" action. It
first disconnects, then revokes the server device and deletes the local tunnel
configuration. The next enrollment is intentionally a new device and follows
the organization's approval policy.

### D5 — Credential reuse must not cross account boundaries (locked)

If a different user signs in on a machine that holds another user's device
configuration, the ownership validation fails closed. The client remains
disconnected and directs the operator to remove/re-enroll the installation; it
does not reconnect with, revoke, or overwrite the other user's device.

## Safety tests

- normal sign-out never calls device revoke and retains the local configuration;
- same-user sign-in after sign-out reuses the UUID, IP and key without another
  approval request;
- explicit removal revokes then clears local state;
- owner mismatch, revoked/deleted state and pending state never arm a tunnel;
- reconnect remains non-destructive and never creates a duplicate device.
