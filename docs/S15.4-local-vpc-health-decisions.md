# S15.4 — directly attached VPC health

## Decision record

### D1 — A local VPC is not a site-link peer

**Decision: locked.** A site with one directly attached gateway and no second site has no
site-to-site WireGuard transit to observe. The CP must not derive `site_link_down` from the
absence/staleness of a peer that does not exist. `site_link_down` remains reserved for a real
remote site-link failure.

### D2 — Health behavior

**Decision: locked.** When the topology contains only one site, suppress the org-level site-link
verdict. The gateway/site remains healthy while its ordinary gateway liveness and subnet-reachability
signals are healthy. This is the minimal correction for a directly attached VPC; a future slice may
add an explicit `local_vpc` label if the UI needs to distinguish it from ordinary healthy state.

### D3 — Scope and proof

**Decision: locked.** This slice changes CP health derivation and unit coverage only. It does not
change AWS routes, security groups, policy enforcement, or site routing artifacts. Tests must prove
that a one-site topology does not produce a site-link-down verdict and that a multi-site topology
continues to report a stale primary as down.
