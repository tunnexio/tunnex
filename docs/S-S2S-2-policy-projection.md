# IPsec source-network policy projection

This pure, unwired compiler input adds `Snapshot.IPsecNetworks`: immutable connection ID, exact assigned gateway/local Site and canonical IPv4 remote prefixes. Only a future qualified runtime service may populate it; disabled configuration inventory is not sufficient authority. No database, API, runtime capability or delivery changes belong to this increment.

An explicit enabled `src_kind=cidr` grant whose entire literal source is contained in exactly one validated remote network may emit only on that connection's exact assigned gateway. The gateway must be bound to the named local Site in the supplied snapshot. Duplicate connection identities, malformed/noncanonical/IPv6 prefixes, remote overlaps or overlap with an approved local Site subnet invalidate IPsec projection. Existing WireGuard-only compiler input and placement remain unchanged.

New remote-source destinations are limited to the assigned LocalSite itself, or an existing CIDR resource fully inside one approved subnet of that LocalSite. Preserve the resource protocol/port/rule ID and literal narrow source. Do not place remote-source entries on co-Site gateways, other Site gateways or the transit hub. Group/device/FQDN/Kubernetes destinations remain outside this projection; do not infer DNS or transit grants. Local Site/source-CIDR grants to remote CIDR resources use existing behavior unchanged.

Remote networks are never inserted into SiteSubnets, device/group source indexes or WireGuard routes. Configuration alone grants nothing. Mesh mode emits no IPsec-specific allows and is not IPsec authorization; the future runtime must use explicit policy enforcement rather than interpreting the existing WireGuard Mesh flag as permission. Removing a qualified network or disabling/removing its rule withdraws its generated entry.

Regression scope: exact multi-gateway placement and L4/source precision, same-Site target bounds, duplicate/overlap/invalid/binding refusals, unsupported source/destination kinds, no implicit mesh/config grants, removal/hash changes and deterministic order, local-to-remote preservation. The current read-time CIDR warning only knows Site placement; future runtime integration must update warning and snapshot population together. This pure increment does not claim user-visible runtime support or change existing warnings.
