# S12.2 — the licence key format and offline verification. Commit-one.

Taken before S12.1 because it makes the issuance work live: a key minted today verifies nowhere
(`grep -rl "tnxl_" apps/api apps/node` is empty). This closes **request → sign → email → paste → verify**.

**IN:** the wire format · Ed25519 verification against a baked-in public key **SET** selected by `kid` ·
fully offline · reading the claims out.
⛔ **OUT:** gating anything on a claim, build tags, the entitlements map — all S12.1. And `tunnex-web` is
untouched except the golden vector.

---

## 1. The wire format — MIRRORED FROM THE SIGNER, NOT REDESIGNED

`tunnex-web/src/lib/licence.ts` already emits this, and it is the authority:

```
tnxl_<base64url(payload JSON)>.<base64url(Ed25519 signature over the payload segment)>
payload = { v, kid, id, dom, band, gw, iat, exp }
```

⚠ **The scope named `tier` and `company`; the signer emits neither.** Ruled by the instruction's own
tiebreak — *match exactly what licence.ts emits* — so: **`band` IS the gateway band, `dom` (the eTLD+1
domain, proven by the trial's email verification) IS the company binding, and there is no `tier` field**,
because Community has no key at all and a field with one possible value gets misread as meaningful.

⛔ **The signature covers the payload segment AS TRANSMITTED.** Verification never re-serialises JSON — Go
and JS disagree on key order and number formatting, and a re-encoding verifier would reject valid keys.

`gw` is resolved at mint (a later band-table change must not silently re-price a key already issued);
`null` means unlimited, never a sentinel.

## 2. The key set, and rotation

The set is a **Go literal, compiled in** — not a file, not config.
⛔ **Baked at build time means a rotation is a RELEASE.** Calling it configuration implies an operator can
fix a compromise; they cannot.
⛔ **An unknown `kid` is a REFUSAL, never a fallback to "the only key we have"** — a fallback turns the set
back into a single key and accepts keys signed by a retired one.

### ⛔ ORDERING PRECONDITION — `tier` AND THE BAND GO INTO THE KEY IN S12.1, NOT BEFORE

**Written beside D4 so the next person meets the reason before the field.**

The key carries `band` and `gw` today; it does not carry `tier`. **That is not a wire-format gap to be
closed here.** There is no gateway limit in the product, no `LicenseManager`, and no enforcement seam —
**S12.1 is unstarted.**

> ## ⛔ **PUTTING A CEILING IN THE KEY BEFORE THE PRODUCT CAN READ IT IS WORSE THAN LEAVING IT OUT: THE KEY
> ## WOULD ASSERT A LIMIT NOTHING ENFORCES.**

That is the render-floor violation **with a cryptographic signature on it** — a claim that is not merely
displayed but *attested*, in an artefact that cannot be recalled. A customer could read `gw: 2` from a
signed licence while running two hundred gateways, and both facts would be true.

**THE PRECONDITION, and it is checkable rather than remembered:**

> **The band goes into the key in the same slice that makes it ENFORCEABLE.** The condition is
> *"enforcement exists"* — verifiable by `grep -rl LicenseManager apps/api`, which is empty today. Not a
> date, not a memory.

⚠ **WHAT THIS MEANS FOR KEYS ALREADY ISSUED, so nobody later reads them as defects:**

- **The walk's key carries no `tier`.** Correct for its moment: nothing could have read one. It is a valid
  key that predates the field.
- **The production key set will not contain the kid that signed it.** The current keypair is test-grade and
  rotates before launch (`tunnex-web/README.md` → PRE-LAUNCH), so that key will verify against no shipped
  build. Also correct — it was a walk artefact, not a customer entitlement.

⭐ **Both are fine, and an unbanded key from before S12.1 is evidence of the ordering being respected, not
of a mistake.**

## 3. ⭐ The golden vector — the story's real work

Signer is TypeScript in `tunnex-web`; verifier is Go here; they must agree byte-for-byte and cannot import
each other.

**One frozen triple — a fixed key pair, fixed claims, the exact wire string — asserted in BOTH repos,
HAND-MAINTAINED IN EACH.** `tunnex-web` asserts *signing these claims produces this string*; this repo
asserts *verifying this string yields these claims*.

⛔ **Never generated, never shared via a package, never fetched.** Derive one from the other and the two
files agree by construction — the failure the twin canonical-hash goldens exist to prevent
(`docs/laws.md`: *a check must be able to DISAGREE with the thing it checks; derivation removes that ability
while looking like rigour*). **The pain of updating two files by hand is the mechanism.** A format change
must break both, or the guard is decorative.

## 4. Refusals — legible, and INERT

`ok` · `malformed` · `unknown_version` (*"needs a newer Tunnex"* — the one refusal whose remedy is an
upgrade) · `unknown_kid` · `bad_signature` · `expired` (report the **date**, not the word).

⛔ **Every outcome is inert this story.** `expired` is reported and the deployment behaves identically.
Grace and enforcement are S12.1.

## 5. The clock — high-water mark

`exp` is checked against the deployment's own clock, which can lie both ways; a backward lie makes an
expired key read as live.

**A persisted high-water mark detects a backward jump and REPORTS it. It never refuses** — a clock going
backwards is overwhelmingly a VM restore, an NTP correction or a stale container image, and refusing would
take a working VPN down over a plausible accident. An attacker with the box can delete the file anyway.
⚠ **Honest instrumentation, recorded as a SUBSTITUTE — not a defence.**

## 6. Fully offline

⛔ **No network call, ever; air-gapped is the promise, not a feature.** Enforced by construction: the
package imports no network package, asserted by a test.
