# IPsec configuration preflight — local validation increment

Implement pure, nonpersisting validation for the proposed AWS public-IPv4 static-routing profile. This closes input-validation groundwork while engine/packaging, provider qualification and runtime contracts are reviewed separately. A valid result means only that input meets this bounded profile; it grants no creation, delivery, activation, route changes or support label.

Reuse `net/netip` and existing PSK validation; no parser dependency, engine command text or cloud API. Explicit fields carry local and remote routed prefixes and exactly two tunnels, each with outside address, inside CIDR, explicit customer/cloud inside addresses and a write-only PSK. Mode is `ipv4-static`. The initial input bound is 1–64 prefixes on each side, a Tunnex preflight limit rather than an AWS service quota. Require canonical IPv4 prefixes and reject duplicate/overlapping ranges within and across sides; tunnel inside ranges cannot collide with these routes or each other. Outside addresses must meet the selected public unicast profile. Provider-specific /30 exclusions and PSK constraints must follow verified primary sources in the companion provider paper.

Errors use static codes and structural locations only, never submitted values or credentials. Invalid data is not silently normalized. Secret fields are omitted from JSON serialization. This helper is not yet attached to the public connection write API or database; new provider fields still need a persisted-configuration contract before storage.

Acceptance: tests before implementation; valid two-tunnel fixtures; IPv6, overlap, malformed/canonicality, duplicate endpoint, reserved inside ranges, host assignment and secret-bound refusal cases; secret-safe serialization/errors; focused tests/race and independent review. Existing UI/theme and active WireGuard paths remain unchanged. Local only; no commit/push, installation or cloud mutation.

## Local evidence — 2026-09-24

Implemented `ValidateAWSStaticConfig` and its explicit `StaticConfig`/`StaticTunnel` inputs. The customer outside address is required as well as both distinct cloud endpoints; addresses must be canonical public IPv4 in the conservative profile and outside the routed prefixes. LANs permit ordinary public unicast and RFC1918; shared address space and other special-purpose ranges are excluded by this initial profile. These are documented Tunnex subset choices, not universal AWS constraints. AWS-specific inside CIDRs and PSK rules follow the dated primary-source [provider paper](S-S2S-2-provider-profile.md).

## Next increment — authenticated configuration check

Expose the pure helper as POST `/api/v1/organizations/{orgId}/ipsec/configuration-check`. Because input includes customer PSKs, require verified human `ipsec:manage` before parsing or validation; use authenticated organization scope. This check does not require opt-in or gateway capability: it only evaluates syntax/profile consistency, not eligibility. Do not read/write provider configuration or add an audit containing submitted values.

Use an explicit generated request DTO with write-only PSKs, mode `ipv4-static`, customer outside address, local/remote prefix lists and exactly two tunnels. Map it into the validator without serializing its internal secret fields. Bound bodies to 128 KiB, require one complete JSON value, and reject unknown properties. Return `{valid:true}` on success. Invalid requests return static codes and structural field/slot information only; never return submitted values, parser details, request bodies or secrets in logs/errors. No success response may claim readiness or connectivity.

Qualification: regression-first route tests for anonymous/unverified/member/machine refusal; auth-before-validation; valid profile; semantic errors; body size/trailing JSON/unknown-field refusal; error/log redaction and no echo. Generated server/CLI/TypeScript artifacts must match the contract. This endpoint is independent of pending provider persistence decisions and adds no migration or creation/activation action.
