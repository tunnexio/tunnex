# S20.5: continuing renewal after an extinguished owner

2026-09-06. Decision under the user's essential HA-fix authorization: implement
and independently review a narrowly proved **renewal-only exclusion** for the
retired owner of a completed handoff. Do not deploy until the negative safety
controls pass. This follows the sustained active-fault failure recorded in
[AWS evidence](../walk-artifacts/S20.5/aws-20260905/ha-wake-repair.md).

The unchanged-content repair remains valid. The new failure is genuine changed
base content on the absent previous owner, whose missing ACK currently prevents
the healthy promoted owner from renewing after its initial serving lease.

## Locked boundary

Completed fencing can discharge a retired owner's dependency for **continuing
current-owner renewal**, never its future candidate-admission obligation.

- Require exact complete durable handoff into the current owner/generation,
  matching org/site/cluster/pool and current membership incarnation, with
  persisted CAS/audit, prepared/serving acknowledgement and expiry/withdrawal
  evidence. Historical, incomplete, conflicting or failed operations do not count.
- Use the conservative expiry path initially: every issued serving delivery to
  that old owner in the exact pool must be expired plus the existing clock-skew
  margin. Include unACKed deliveries. Absence, status and health alone never
  establish extinguishment. Do not alter lease durations or skew.
- Keep complete topology, every fence and every ordinary authority delivery.
  Do not fabricate ACKs, delete membership or relabel stored evidence. Current
  owner and all unrelated members retain their exact full-base ACK requirements.
- A node excluded for pool X confers no exclusion for another pool. Any remaining
  required scope still blocks that node's incomplete authority batch.
- Do not renew the excluded node's prepared envelope. Prevent promotion/failback
  using any older still-live prepared receipt until its latest exact ordinary
  authority for the current pool generation is genuinely ACKed. Check this at
  candidate admission as well as renewal; issuance omission alone is insufficient.
- Revalidate exact leadership, topology, membership and exclusion through lease
  issuance. No global missing-standby bypass, protocol change or node fence change.

## Required proof before deployment

Complete a durable A-to-B handoff using real proof boundaries, leave A absent
with genuinely changed base content, ACK B/other required members, then renew B
past multiple initial lease horizons while A remains unACKed and non-serving.
Return A and prove that only exact current base acceptance restores preparation
and candidate admission. Negative controls cover live unACKed old leases,
stale generation/membership, incomplete handoff, missing current-owner or unrelated
standby ACK, and multipool overlap. Preserve ordinary changed-base strict tests.

Re-run only this affected API/fencing slice in both editions, obtain independent
review, publish only a new API candidate, then repeat the failed active-owner
sequence on restored AWS infrastructure. The passing standby sequence remains
evidence, not an instruction to reconstruct the cluster or replay eleven legs.

Implementation boundary: compile outside database locks as before, then perform
ordinary authority maintenance, exclusion proof and prepared/serving insertion
inside one owned transaction. Split the existing v3 insert from its committing
wrapper rather than accidentally committing the first envelope early. A failed
later insertion must roll back the earlier preparation and all batch writes.
The strict non-renewing maintenance entry point keeps its all-member behavior.
Production passes the same configured clock-skew margin to the coordinator and
renewal proof; zero margin retains the strict path rather than inventing a default.

Candidate admission remains guarded during draining and after the operation's
CAS: current owner/generation changes must not switch the guard off. Missing or
achieved-legacy transitions retain their prior candidate contract; no default-off
enforcement is introduced.
