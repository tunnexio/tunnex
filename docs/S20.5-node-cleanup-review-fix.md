# S20.5 node cleanup review fix

Status: implementation note for the S20.5 review fixes. This note does not
change the locked D10/D11/D11a product contract and does not enable the S20.6
ordinary host-reboot rebootstrap deferral.

## Scope

This fix closes two node-agent defects from `S20.5-review-findings.md`:

1. last-owner cleanup could delete the exact journal-owned `wg0`, then fail or
   crash while restoring a later primitive, leaving the durable journal
   `active` with a committed link receipt that could never be prepared again;
2. a failed `ip ... addr show` observation was collapsed into an empty tunnel
   CIDR, which the Kubernetes network-preparation reconciler correctly treats
   as an explicit withdrawal and therefore removed its last-good owned CNI
   bypass rule.

The repair remains provider-neutral and uses only the existing host journal,
exact Linux ownership receipts, and injectable command seams.

## Durable teardown-intent state

The journal gains one closed state, `restoring`. It means all of the following
facts were durably published before teardown began:

- an authoritative successful exact-node owner read proved the owner set empty;
- the journal's owner set is empty;
- this exact ownership epoch is committed to finish bounded D10/D11 cleanup;
- absence of a previously journaled artifact can therefore be an idempotent
  cleanup result, rather than evidence authorizing active-state rebootstrap.

The state transitions are:

| Durable state | Live owner observation | Allowed action | Next durable state |
|---|---|---|---|
| `preparing` / `active` | one or more owners | prepare/enforce the exact epoch | `active` |
| `preparing` / `active` | proven empty | persist empty owners, then persist teardown intent | `restoring` |
| `restoring` | any successful owner observation | finish only the old epoch's exact idempotent cleanup; never enforce or adopt a missing link | `restored` |
| `restoring` | API error or ambiguous observation | no kernel mutation; retain teardown intent and publish blocked | `restoring` |
| `restored` | one or more owners on a later pass | capture a fresh baseline and start a new epoch | `preparing` |

Cleanup is never entered until the journal store has durably published
`restoring`. A store failure before that boundary causes zero cleanup
mutation. Every cleanup primitive remains exact and idempotent: already-absent
owned CNI/Docker/routes/nftables/staged-or-final WireGuard artifacts are
accepted only under their existing journal signatures, and sysctls are restored
only while the live value still equals the Tunnex desired value. A primitive
failure or a crash before the final `restored` write leaves durable
`restoring`; the next conclusive pass resumes the old cleanup and only a later
pass may create a fresh ownership epoch.

`restoring` requires an empty durable owner set. This prevents malformed state
from turning a journal with retained owners into cleanup authority. If owners
reappear while teardown is already durable, the manager completes the old
epoch first and publishes idle for that pass; it does not splice new owners
into a partially removed epoch. Admission remains closed until the next pass
creates and fully prepares a new epoch.

### Explicit S20.6 boundary

An `active` journal with a committed receipt and a missing final link still
fails closed. Only a prior durable `restoring` transition makes missing exact
artifacts a cleanup-retry intermediate. The fix does not reset committed
receipts, recapture a post-reboot baseline, or recreate an absent active link;
ordinary host-reboot rebootstrap remains deferred to S20.6.

## Tunnel-CIDR observation grammar

The WireGuard IPv4 address read is a three-way observation:

| Observation | Meaning | Kubernetes network-preparation action |
|---|---|---|
| command succeeds and yields a valid primary IPv4 CIDR | known active tunnel CIDR | reconcile the exact CIDR; later DNS VIP address lines do not replace the primary tunnel subnet |
| command succeeds and yields no IPv4 CIDR | known absence | explicit withdrawal |
| command fails, is cancelled, or yields invalid output | unknown | return blocked/error, retract readiness, preserve the last-good owned adapter rule |

Only known absence is passed to the reconciler as an empty CIDR. Unknown never
calls the withdrawal path and never renders a replacement egress ruleset from
an invented empty subnet. The existing injectable `ip` output runner is the
observation seam, so regression tests need no host network privileges.

## Deterministic regression matrix

- journal-store refusal while publishing `restoring`: assert zero cleanup calls;
- real staged-link primitive deletes the exact committed link, then a real
  sysctl-file read fails: assert durable `restoring`, blocked heartbeat, and a
  second manager/kernel instance completes cleanup with the link already absent;
- simulated crash/final-store failure after all real cleanup primitives: assert
  durable `restoring`, then successful replay reaches `restored` without a
  second link deletion;
- `active` plus committed receipt plus missing link and a live owner: assert
  fail-closed behavior remains and no link is recreated (S20.6 guard);
- injected `ip` read failure after a ready CNI reconcile: assert no reconcile or
  withdraw call, readiness becomes false, and the error is surfaced;
- successful empty address output: assert the explicit withdrawal path still
  runs and remains not ready;
- successful valid address output: assert the exact CIDR reconcile remains
  ready.

All tests use temporary sysctl fixtures and fake command/link runners. They do
not execute manual host-network operations.
