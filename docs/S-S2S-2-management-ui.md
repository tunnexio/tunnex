# IPsec management UI — local implementation slice

Build a concise desktop creation/readback flow inside the existing Site-to-site Connectivity workspace. Reuse the current theme and components; preserve default WireGuard review. Add a WireGuard/IPsec method switch, lazy-load IPsec data, show stored configurations as Disabled/Deleted rather than connected, and keep unsupported-runtime messaging explicit.

Existing org:view allows inventory/nonsecret configuration reads. Only a verified owner/admin (ipsec:manage) gets opt-in or create/delete controls; site-manager access alone is insufficient. Settings changes are explicit CAS actions, never automatic prerequisites. Saving creates a disabled configuration; no activation, runtime, cloud, new persisted model or new permission is introduced.

The creation form selects existing Site/gateway and exact approved local subnets, with explicit customer outside address, remote prefixes, and two tunnel assignments/PSKs. Keep explanatory text short and use field labels/grouping. Secrets stay in component memory/password inputs only: no browser storage, URL, logs, query cache or readback; clear on cancel, successful save, user/org/scope changes and unmount. Do not imply full memory erasure. Preserve selected UUIDs across ambiguous retry rather than creating duplicate identities; after uncertainty, reconcile the existing identity before changing its draft. Surface errors/retry without displaying raw server values.

Readonly GET `/api/v1/organizations/{orgId}/ipsec/eligibility?site_id=UUID&gateway_node_id=UUID` supplies the missing display prerequisite. Require org:view, Cache-Control:no-store; return `{eligible,reason}` where reason is eligible, opt_in_required, gateway_unavailable, unsupported or report_stale. Read current live-org opt-in and selected-site gateway enrollment/revocation/status/capability/report receipt in a consistent read-only snapshot using DB time. Share eligibility predicates with authoritative create. Unknown/cross-org selected gateway is unavailable; no credentials or node capability blob exposed. No write/version/audit side effect. A positive result is advisory eligibility only; POST rechecks all ownership/range/capability gates under locks. Current production nodes remain capability0.

UI must immediately withdraw old scoped records/forms/secrets on org/auth change, ignore late responses, and refuse saving when selected gateway eligibility is missing/stale/negative. Server validation and create still enforce correctness. Inventory follows existing cursor pagination; readback excludes all credentials. Render only approved stored state, with explicit tombstones and no reachability claims.

Acceptance: regressions before implementation; actual eligibility DB read-without-write and refusal tests; frontend create/read, errors, pagination, role gating, secret clearing, stale scope, retry identity and unsupported states; focused then full web tests/typecheck/build; API tests/codegen/build; independent review; rendered desktop inspection. Browser mutations that would create configurations/settings in the review CP are not necessary for visual proof; use isolated test fixtures for supported paths. Local-only, no push.
