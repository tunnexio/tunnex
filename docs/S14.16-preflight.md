# ⛔ CHECK 7 — AND IT FOUND SOMETHING SHARPER THAN THE REGISTERED ITEM

`AuditLog.tsx:213` renders the actor as:

```tsx
{a.actor_id ? actorName(members, a.actor_id) : "system"}
```

**MEASURED against the served payload (100 rows, enterprise stack):**

| shape | rows | renders as |
|---|---|---|
| `actor_id` present (a human) | 40 | the member's name ✅ |
| `actor_system` present (a NAMED subsystem) | 26 | **"system"** — the name is discarded |
| **NEITHER** | **34** | **"system"** — identical to the above |

> ## **SO "system" MEANS TWO DIFFERENT THINGS ON THE SAME SCREEN: *a named subsystem did this*, and**
> ## ***nobody recorded who did this*. AN UNATTRIBUTED ROW IS INDISTINGUISHABLE FROM AN ATTRIBUTED ONE.**

The registered finding was *"the Audit Log discards every named `actor_system`"* — true, and the smaller half.
**The larger half is that discarding it makes an ATTRIBUTION GAP invisible**, because the fallback word for
"unknown" is the same word used for "known, and here is its name".

## AND THERE IS A SERVER HALF — third instance of the class S14.15 just fixed twice

Confirmed in the database, not inferred from the API: four actions write audit rows with **neither**
`actor_user_id` nor `actor_system`:

```
hub_set.promotion · hub_set.failback · hub_set.membership · node.enrolled
```

These are system-initiated — an HA controller promoting a hub, a node enrolling — and they use the HUMAN
insert path with a NULL actor instead of `InsertSystemAuditLog`, **which already exists and was already used
elsewhere**. Same shape as `UnmapGroup` and `SuspendDomainClaim` (S14.15): the primitive was there and the
call site did not reach for it.

**Registered, not fixed here.** Naming each of the four correctly is a server change per call site, and it
should carry the `device-health` / `idp-sync` / `domain-capture` naming convention with it rather than being
guessed one at a time.
