# S20.5 retained-state review fix

Status: authorized narrow fix for review findings 12 and 21; CLI enforcement
and deterministic local proof are implemented in the isolated integration
lane. The direct-Helm remainder below is still open.

## Problem

Before this fix, the lifecycle CLI accepted `--mode reuse` after checking only
the retained PVC's release-shaped metadata, stable Bound identity, and absence
of a live mount. It did not bind the claim to the selected control-plane
organization or prove that the PVC's immutable lifecycle claim was consumed by
one canonical node identity.

The enroll retry path also permitted an already-present same-release PVC to
reach Helm without first proving that its organization and lifecycle-claim
annotations equalled the retained lifecycle anchor. Helm could otherwise merge
new annotations onto old bytes and make retained identity state claim
provenance it never had.

## Decision

For a lifecycle-CLI reuse, the existing PVC is identity authority and all of
the following are required before host-posture, token, namespace, or Helm
mutation:

- exact retained Helm/Tunnex metadata for the requested namespace, release, and
  claim;
- both `tunnex.io/organization-id` and `tunnex.io/lifecycle-claim`, each an exact
  canonical non-nil UUID;
- equality between the PVC organization and the freshly resolved, explicitly
  selected current membership;
- control-plane readback of that exact claim in that exact organization;
- `consumed` state with a real consumption timestamp and one canonical non-nil
  bound node UUID.

The canonical lifecycle claim selected by the PVC and the canonical node UUID
bound to it are the immutable identity proof. `--node-name` remains a chart
runtime/display input; neither that value, the claim's historical node-name
field, nor a live node lookup by name can authorize reuse or substitute for the
claim-to-node UUID binding.

The PVC organization and claim join the approved state fingerprint. The same
facts are re-read after approval and after Helm, so reuse cannot invent,
replace, or normalize provenance.

For enroll retry, an existing PVC is accepted only when its exact canonical
organization and lifecycle claim already equal the owned lifecycle anchor.
Missing, partial, malformed, or foreign provenance refuses before mutation;
Helm never receives a chance to relabel it. An ordinary first install still
requires the PVC to be absent.

## Legacy boundary

A pre-contract or direct/manual Helm PVC with no lifecycle provenance cannot be
proved as a zero-touch CLI lifecycle. The CLI refuses it rather than treating
missing annotations as fresh, absent, or terminal control-plane evidence.
Direct/manual Helm `reuse`, which mounts an explicitly named claim without a
token and makes no zero-touch proof claim, remains the legacy compatibility
path. Partial or malformed provenance is never legacy.

## Proof

Dedicated deterministic tests must cover:

- valid same-organization reuse with exact consumed/bound-node proof;
- cross-organization refusal before host-posture, token, namespace, or Helm
  mutation;
- missing, partial, malformed, absent, non-consumed, wrong-node, and
  non-canonical bound-node lifecycle evidence, including proof that a matching
  mutable node name cannot rescue a mismatched claim;
- same-release enroll retry with matching provenance; and
- refusal of missing or foreign enroll provenance while preserving the exact
  PVC/anchor/Secret fixture bytes and issuing no mutating command.

## Direct Helm remainder

CLI validation cannot protect a direct `helm install`. Full resolution of
finding 21 also needs a chart-side live-PVC pre-install guard: enroll must fail
when the would-be claim already exists unless both canonical provenance
annotations exactly match the supplied lifecycle provenance. An existing
unannotated PVC must use tokenless `reuse`; it must never be relabelled by an
enroll render. This document does not authorize or implement that chart change.

## Implementation and local proof

`discoverInstallState` now refuses lifecycle-CLI reuse unless the retained PVC
has exact Helm ownership and canonical organization/claim provenance. Before
host-posture discovery, `prepareInstall` resolves the selected membership and
requires the exact control-plane claim to be consumed with a canonical request,
generation, consumption time, and bound node UUID. Those immutable facts join
the approved fingerprint and are re-proved after approval and after Helm.
Retained-state Lease resume or expired-holder takeover also re-proves and
repopulates that control-plane identity before comparing the approved
fingerprint, preserving crash recovery without weakening the new binding.

The enroll retry path now requires an existing same-release PVC's provenance to
equal its owned lifecycle anchor before Helm can adopt the claim. It never
writes or normalizes the existing PVC.
