# S15.12 — Client shell regressions

## Scope

Correct the desktop regressions observed after RC21 without changing tunnel, API, or
control-plane behaviour.

## Decisions

- **D1 — Window shell: locked at 400 × 740.** The prior 440px shell looked unnecessarily wide;
  400px remains compact, while 740px gives the mesh and fully legible structured counters enough
  vertical breathing room without a cramped or scrolling primary surface.
- **D2 — State-invariant metrics geometry: locked.** Connected and disconnected reserve the
  same graph-summary row. Metric labels and values stay on one line, truncating only a value
  that cannot fit, so a state change cannot move the action or stretch the card.
- **D3 — Tray source: locked to deterministic transparent PNG assets.** Electron's macOS tray
  uses packaged 16/32px PNGs rather than SVG data. Asset tests prove visible, centred artwork and
  a transparent corner. Native menu-bar rendering is substituted by the CI macOS packaging job;
  the named trigger for an on-device proof is the next signed macOS release candidate.
- **D4 — Native local launch: rejected.** The Founder asked not to launch Electron or the helper
  locally. Browser preview plus focused tests are the local proof; native packaging remains CI's
  responsibility.
- **D5 — Orbit hub primary action: locked.** The centre interaction is one neutral white pearl in
  both states. While disconnected, a segmented halo and periodic “Click here” cue make it
  discoverable; when connected, the halo settles and a persistent “Disconnect” caption names the
  action. Red remains reserved for faults and policy blocks, never for normal tunnel control.
- **D6 — Account and imported profiles are parallel connection sources.** Choosing “Use Tunnex
  account” safely brings the active imported tunnel down and deselects its file, but never deletes
  it. The next connection therefore resolves through the enrolled device or sign-in flow; choosing
  an imported file remains an explicit, equally safe switch in the other direction.
