## Exact infrastructure and IAM effects

`deploy/aws-s205-walk-controllers.yaml` creates a **new** stack named
`tunnex-s205-aws-20260905a-controllers`:

- Two CloudFormation-named IRSA roles. Trust fixes the issuer, audience
  `sts.amazonaws.com`, and exactly `kube-system:ebs-csi-controller-sa` or
  `kube-system:aws-load-balancer-controller`. No wildcard subjects, static AWS
  keys, worker-role attachments, or existing IAM policy edits.
- EBS managed add-on, one controller replica, snapshots disabled, no default
  StorageClass. This is minimum walk capacity, not controller HA. Version 1.65
  automatically adds the cluster-name ownership tag as an EKS add-on; the IRSA
  role carries `eks-cluster-name`. The managed policy confines write access to
  cluster-tagged volumes/snapshots and attach/detach to cluster-tagged nodes;
  an inline deny prevents EC2 operations outside Mumbai. Discovery remains
  read-only `Resource: *`. AWS-managed policy updates are not immutable; re-read
  its default version before execution. Do not import or retag existing volumes.
- One shared NLB frontend SG: UDP 51820 from a freshly verified client public
  **/32**, with no committed CIDR default. Outbound permits only UDP 51820 and
  TCP 9091 to the exact task worker SG. Two new stack-owned ingress rule
  resources add those ports **from the frontend SG** to the task worker SG.
  This is a real, explicitly scoped modification of that task SG; it neither
  replaces its rules nor touches the protected demo SGs.
- LBC permissions are derived from the versioned upstream IAM action list and
  reduced to regional read-only discovery, the two named NLBs, their listeners,
  and target groups carrying this exact cluster tag. Creation fixes internet
  scheme, supplied SG, and the two subnets. No EC2 writes, IAM writes, ALB,
  certificate, WAF, Shield or route/DNS permissions. TG IDs are allocated at
  runtime, so their ARN suffix is wildcarded with the exact ownership tag.
  Listener ARNs are constrained by their two parent NLB names. This custom
  least-scope policy still needs live controller reconciliation proof; an
  unexpected AccessDenied is a stop-and-inspect event, never permission to
  attach the broad upstream policy to a worker.
- `AWSServiceRoleForElasticLoadBalancing` was absent (`NoSuchEntity`). The stack
  creates AWS's required **account-wide service-linked role**, not a task-scoped
  customer role; it is retained on stack removal because later consumers may
  share it. Reverify absence before creation. LBC cannot create IAM roles.


Default AWS-managed EBS encryption is used; no custom KMS key or KMS grants.

WaitForFirstConsumer does not make a bound volume cross-AZ portable. Retain
means neither deleting a PVC nor uninstalling Helm authorizes volume deletion.
