## P1 — healthy owner's renewal depends on pending standby base ACKs

The durable live ledger shows A3 serving generation 3 / epoch 110 expiring
at 02:19:30 UTC, with no next serving delivery until 02:20:27. Exact full-base
ACKs arrived at 02:20:06 for A3 and 02:20:22 for B2. Traffic recovered at
02:20:30. The owner did not change. B2 was absent and then returned at
02:19:32: the expiry predates its return, so this is not evidence that pod
return alone caused the outage.

`handoff_ha_runtime.go` deliberately gates renewed serving/prepared envelopes
on scope-complete maintenance acceptance. This is a safety contract, not an
accidental unchecked condition to remove. Per-node base hashes stayed stable
while exact base versions changed in the observed window.

Recommended next step: paper the relationship between ordinary base versions,
accepted pool classification, current-owner lease renewal and standby eligibility.
Prove which updates genuinely require a new barrier before choosing any repair.
Preserve exact scope/hash/generation checks and fail-closed behavior for real
topology changes; do not merely lengthen leases, skip standby ACKs or add a
notification loop that itself advances desired-state versions.

## P1 — credential promotion has an immediate-uniqueness ordering defect

Exact-source enterprise gates reproduce SQLSTATE 23505 at the one-current
credential index. `AuthenticateAgentRuntimeCredential` promotes a candidate
and demotes its predecessor in one unordered multi-row UPDATE. Candidate-first
visitation violates the index. Uniform unauthorized handling is an availability
failure, not evidence of unauthorized access. Affected code is unchanged from
the integration baseline; that comparison is not a full baseline gate run.

Recommended bounded repair: an explicit transaction with common device-row
then credential-row lock ordering, re-read exact credential binding after
acquiring the device lock, demote the exact predecessor before promoting the
exact candidate, and roll back any incomplete transition. Rotation/preparation
must use the same serialization boundary. Retain the unique index and uniform
refusal. Add concurrency, replay, expiry-during-lock-wait, rollback and device
revocation tests in both editions; no nontransactional fallback.

## P2 — startup desired-state 500 terminates the returning container

A3's first returning container exited after the exact-base-authority mismatch
at 02:17:01 UTC. Kubernetes restarted it once. Existing startup execution
returns before lifecycle reconciliation initializes lease state; arbitrary
retry is not a safe local patch. The mismatch message alone does not identify
whether version or hash differed. Keep automatic failed-candidate recovery and
ordinary reboot rebootstrap in their named deferrals; do not call operator
recovery or automatic container restart zero-touch lifecycle acceptance.

## P2 — two independent integration fixture isolation defects

Bootstrap tests reuse a globally unique fixed token hash. Their ignored hard
organization-delete cleanup fails because immutable audit records reject the
FK's SET NULL update. Runtime tests instead close their pool before registered
cleanup, which also ignores errors. Both leak fixture state.

Recommended isolation: fresh uniquely named disposable test databases with
normal migrations and explicit, observable bounded teardown. Do not relax
production audit triggers, delete shared fixtures, or fix only the token
literal while retaining silent cleanup failures. Database creation/removal
must be constrained to fixtures created by that test, never default Compose
stores or the live CP.

## P2 — agent health report fields are dropped by HTTP decoding

The node sends `k8s_endpoints_unavailable` and `conntrack_flush_unavailable`;
the API's report-info body and `AppliedPolicy` mapping omit them. Persisted
false values therefore cannot prove a healthy endpoint watcher. This does not
establish either flag as the cause of the measured lease gap.

Recommended existing-contract correction: carry both fields through the HTTP
handler and add true/false/missing-field round-trip tests. Do not change HA
health thresholds or silently reinterpret old-agent missing values.
