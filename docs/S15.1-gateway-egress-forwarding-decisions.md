# Gateway full-tunnel egress forwarding — decisions

## Problem

On Docker-hosted gateways, split-tunnel traffic works but full-tunnel IPv4 traffic
stops at the gateway. WireGuard handshakes succeed and ICMP requests arrive on
`wg0`, but no packet leaves the host's external interface (`ens5`).

## Root cause

The node agent renders its own `ip tunnex` forward and postrouting chains. Those
chains contain the scoped WireGuard-pool accept and masquerade rules. Docker also
installs a separate `filter FORWARD` base chain with policy `DROP` and a
`DOCKER-USER` hook. A verdict in the separate `ip tunnex` base chain does not
clear Docker's later policy drop. The agent's Docker reconciliation did not emit
the pool-class `DOCKER-USER` accepts when the desired policy did not carry a
`PoolCIDR`, leaving `DOCKER-USER` empty. RC11 therefore restored NAT but did not
close this Docker forwarding gap.

Evidence from Gateway 1 and Gateway 2:

- WireGuard latest handshake and transfer counters advanced.
- `10.99.0.x → 1.1.1.1` requests were captured on `wg0`.
- No corresponding ICMP packet appeared on `ens5` until narrowly scoped
  `DOCKER-USER` accepts were installed manually.
- After those accepts, request/reply packets appeared on `ens5` and full tunnel
  internet worked.

## Proposed implementation

1. Make the agent derive the IPv4 device-pool CIDR from the active WireGuard
   interface when the desired policy's `PoolCIDR` is empty, using the same
   validated subnet already used for masquerade.
2. Reconcile two scoped, idempotent `DOCKER-USER` accepts per tunnel interface:
   - `wg0 → external`, source limited to the device pool;
   - established/related `external → wg0`, destination limited to the device pool.
3. Keep the existing `ip tunnex` policy as the security authority. The Docker
   rules only remove Docker's structural drop and must never become blanket
   `ACCEPT` rules.
4. Full-sweep stale marked rules on every reconcile, and expose a loud
   `forward_blocked` status when placement fails.
5. Add unit/golden tests for an empty-policy-pool Docker host, idempotence,
   stale-rule removal, and non-pool denial. Verify both IPv4-only and dual-stack
   gateways; IPv6 remains fail-closed unless its verified egress path exists.

## Release and rollout

- The fix must ship in a new immutable node-agent image; re-pulling RC11 is not
  sufficient because RC11 contains the observed gap.
- Existing gateway state volume and enrollment identity remain unchanged.
- Validate on Gateway 1 and Gateway 2 with handshake, `wg0` counters, `ens5`
  packet capture, and an end-to-end IPv4 full-tunnel probe before tagging.

## Non-goals

- No blanket host `FORWARD ACCEPT` policy.
- No disabling Docker firewalling globally.
- No manual firewall rule as the product fix; manual rules are diagnostic only.
