# S20.5 immutable lifecycle claim binding — finding 14

Status: implemented contract-preserving defect fix; lifecycle/node and migration
tests pass in both API editions. Full API gates remain red on the separate
failures recorded below. No migration or API shape change. Existing D13 claim
identity remains authoritative after node rename.

The token already records `consumed_node_id`; the node records its exact
organization and lifecycle claim. Requiring a live node's mutable display name
to keep matching the original enrollment name contradicts that identity model
and wedges install completion/abort after an ordinary rename.

Use one positive binding check whenever a present node authorizes lifecycle
status or abort: positive generation, a consumption timestamp, a non-nil
consumed UUID equal to the node UUID, exact organization equality, and exact
non-nil claim equality. A matching display name cannot rescue a wrong UUID,
organization, or claim. Generic binding permits active or revoked nodes;
completion still independently requires active, and terminal-abort replay
still independently refuses a surviving active node. Historical token name
and request-name CAS pins remain unchanged.

Completion SQL retains its ID/organization/claim join and removes only the
live display-name equality. Initial enrollment authorization, immutable
request pins, initial-consumption deferred checks, N-1/current migration
bridges, and all migration bytes stay unchanged. The initial-consumption
trigger is not re-fired by a later node rename.

Preserve exact deletion semantics: `node == nil` and a NULL consumed-node ID
can represent terminal history after FK `ON DELETE SET NULL`. A retained
consumption timestamp keeps it consumed and prevents remint; aborted history
remains aborted. No node ID is invented or returned. A non-NULL consumed ID
with no matching organization/claim node is inconsistent, not valid absence.
Generation-zero tombstones remain credentialless and node-free. The canonical
revoked-node deletion path still deletes its token first and cascades its
install operation; this repair resurrects nothing.

Status currently reads token then node in READ COMMITTED. Before validating
their positive binding, use the existing token-row lock in the established
token-to-node order so consumption or token deletion cannot cross the proof.
Do not add a node lock or weaken a mutation fence.

Regress rename before completion, legacy abort, coordinated abort and terminal
replay; wrong UUID/org/claim and unconsumed binding refusals; active/revoked and
node-only-deleted terminal cases; unchanged generation-zero, revocation and
initial name-pin behavior; and concurrent status versus first consumption.
Run the real PostgreSQL tests, regenerate sqlc, and rerun both API editions.

## Implementation and proof — 2026-09-05

`validateLifecycleNodeBinding` is the shared positive identity check for status
and abort. Status takes the existing token-row lock before its node read.
Completion removes only the mutable node-name predicate; `make sqlc` regenerated
the corresponding one-line query change. All migration bytes remain identical
to integration commit `ae458ffd89722117dce959e07eaa0c1144279111`.

The new unit and PostgreSQL tests in
`apps/api/internal/nodes/lifecycle_claim_binding_test.go` and
`apps/api/internal/nodes/lifecycle_claim_binding_integration_test.go` prove:

- rename before completion, legacy abort, coordinated finalization, and terminal
  replay preserves the exact consumed node; the original request-name pin still
  refuses a request that substitutes the renamed display label;
- wrong or missing consumed UUID, missing consumption, foreign organization,
  and missing or foreign claim refuse status/completion; failed abort
  finalization rolls back its operation, token, audit, and node effects;
- terminal replay independently refuses a surviving active node and corrupt
  bindings; generic consumed status still accepts the exact revoked node;
- node-only deletion preserves consumed/aborted history without inventing a
  node ID, forbids remint/completion, and permits terminal abort replay;
- canonical revoked-node deletion removes the node, token, and operation;
- a status read waits on the exact first-consumption transaction, observed
  through PostgreSQL `pg_blocking_pids`, and returns the committed consumed
  binding after that transaction finishes.
