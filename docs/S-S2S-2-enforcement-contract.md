# S2S-2 — IPsec enforcement, ownership and recovery contract

Status: proposed implementation contract, 2026-09-24. Written before production enforcement, allocator or journal code. This paper authorizes no host, namespace, database, cloud or remote mutation. It defines the safety gate for completing the runtime; synthetic booleans alone do not satisfy it. Engine and delivery contracts are separate, coordinated dependencies.

## Existing seams and preserved behavior

`apps/node/internal/egress/egress_linux.go` owns `ip tunnex` and `ip6 tunnex`. Its forward chain has priority `filter` (0), an early established/related accept, a native-interface passthrough, and compiled policy rules. Its NAT priority is `srcnat - 1` (99). An IPsec guard cannot rely on those accepts to implement revocation. `tunnelIfaces` currently authenticates WG/OpenVPN only; adding a physical LAN device would widen trust and is prohibited.

`apps/node/internal/reconcile/routeownership.go` reserves WG route metric8021 and return-rule priority100. IPsec must not adopt these ownership selectors. `FQDNConntrackMarkMask=0x0f000000` and value`0x01000000` belong to FQDN flow recovery; preserve them and all unrelated marks. Docker/CNI integration remains separately owned. No global nft, XFRM, route, conntrack or credential flush.

The API policy compiler already supports site/CIDR subjects. Despite the old node `AllowEntry.SrcIP` comment, compiled source values can be CIDRs. Reuse the existing source/destination/protocol/port semantics. Provider remote prefixes are connection-owned resources, not fabricated Sites. Extend the authoritative compiler projection for the assigned gateway where necessary; never convert provider configuration into an implicit grant or broaden existing shared Site authority.

## Independent refusal boundary

A single node IPsec enforcement owner manages a dedicated `inet tunnex_ipsec` table, outside tables the existing egress manager flushes. Verify a versioned owner marker and complete semantics before changing an existing table; a same-name foreign table is a collision. One serialized command lane owns journal transitions, nft changes, route selection and cleanup. Processes must also hold an exclusive node runtime lock; Go mutexes alone do not prevent two agents.

The table contains forward and output filter base chains at priority-10, after destination NAT but before the existing filter chains, plus a postrouting filter chain at priority90 before existing masquerade. An input chain at priority-10 denies unexpected tunnel-to-gateway payload. These are candidate numeric reservations: enumerate existing hooks and refuse a conflicting deployment whose ordering cannot be proven. No silent re-prioritization. Runtime lab must establish actual packet paths, including XFRM reinjection; a renderer test does not prove hook placement.

For each journaled connection, keep immutable protected remote-prefix sets and its two exact XFRM interface identities. Destination protection applies to all local and forwarded sources: an unauthorized source must not escape through ordinary routing simply because it is outside configured local prefixes. Source protection rejects packets claiming the connection's remote prefixes on any ingress other than its verified XFRM interfaces. Match interface index together with validated namespace/name/XFRM-ID ownership; names alone can be replaced. Ordinary trusted LAN ingress is explicitly resolved from the assigned approved local subnet and live link identity. It never joins the authenticated tunnel set.

Every payload rule has these properties:

1. Before any conntrack shortcut, a packet for a protected remote destination must use the currently permitted owned XFRM output interface and match a current grant. Otherwise drop. The postrouting barrier repeats the no-cleartext condition so route/object loss cannot fall through to a physical default route. Include gateway-originated OUTPUT traffic; no host-originated implicit permission.
2. On either assigned XFRM ingress, require the connection's exact remote source prefixes, approved destination domain and directional grant. Reject wrong source, other-connection sources, tunnel-to-tunnel transit without its own grant, and unexpected gateway-local destinations. The shared policy compiler defines permission, not SA traffic selectors.
3. Established/related state never bypasses connection enable state, current grants or anti-spoof checks. Reply permission comes only from a still-authorized original directional tuple plus exact tunnel/local domains. Unsupported conntrack/protocol representations refuse; no blanket established accept in the guard. Scoped conntrack deletion is hygiene and cleanup proof, not the immediate enforcement boundary.
4. A guard allow only continues to the existing firewall. Existing WG/OpenVPN policy may still deny. Integrate verified XFRM interfaces into the existing tunnel boundary only under the same acknowledged policy revision; retain guard denial throughout any multi-owner transition. Do not rely on a native-forward shortcut for IPsec allow proof.
5. No NAT of IPsec inner local/remote traffic in this profile. Verify the existing and foreign NAT chains do not rewrite the protected tuples. Unsupported deployment NAT behavior blocks activation rather than adding a broad bypass.
6. Unknown, disabled, stale, revoked or cleanup-pending assignments have no payload permit entries. IPv6 is not supported by the initial AWS IPv4 profile; no IPv6 route/selector/permit is synthesized.

Initial static profile validation already rejects peer/customer outside addresses overlapping payload prefixes. Recheck that invariant in authenticated node intent. The node owns explicit payload routes; the daemon installs none. Thus no new payload/conntrack mark is needed in this initial profile, and the underlay remains ordinary routing. A peer-address exemption must never become permission for arbitrary payload. Expanding to default routes or overlapping underlay requires a separate marked-routing contract.

A successful guard transaction yields a nonsecret receipt bound to node, connection, desired/configuration/policy revisions, network-namespace identity, immutable manifest digest and observed guard generation. This receipt is created only after exact readback; an arbitrary `installed=true` supplied by the caller is not sufficient. Establishing SAs requires a refusal receipt. Publishing permits additionally requires matching fresh daemon, SA, link, route and policy evidence. Any error reports pending/failure, never applied success. If replacement of an already-permitting ruleset fails, the kernel can retain old permits; an ordinary atomic transaction alone does not establish immediate revocation. Production requires the independent authority-expiry mechanism below before activation can be qualified.

## Allocator and durable journal

Use a separate versioned, root-owned node journal under the existing private node state root; do not overload the Kubernetes ownership-lease schema. Reuse its bounded strict JSON, duplicate-key rejection, checksum,0600 temporary file, fsync, atomic rename and directory-fsync techniques. Add exclusive process locking and reject symlink/foreign ownership paths. Checksums detect corruption, not malicious-root tampering. Store no PSK, ciphertext, SA keys, provider request body or raw diagnostic output.

Immutable allocation identity is organization/node/connection/tunnel/slot plus a random allocation generation. Record namespace identity, interface name, XFRM-ID, interface index once created, ownership alias, table, route protocol/metric, destination rules, protected-prefix manifest and assigned configuration digest. Desired revision and stage checkpoints are monotone; changes create journal successors rather than rewriting the immutable identity. Interface indices are observations, not stable allocation IDs: after reboot they require fresh creation/adoption proof, never reuse from disk as fact.

Candidate allocator policy: deterministic bounded probing from the authoritative identity, maximum4096 attempts; interfaces use a bounded `tnxi` prefix plus identifier; XFRM IDs nonzero uint32; private routing tables10000–19999 and rule priorities20000–29999, route protocol242 and metric0 within the dedicated table. These are internal choices, not public contracts. Enumerate live links/XFRM IDs, complete route/rule tables and all journal reservations first. Refuse foreign collisions or exhaustion; never overwrite. Preserve WG metric8021/rule100 and all marks. Before implementation validate this candidate range against the repository-wide ownership registry and fixture host; amend this paper if a collision is found.

Per-connection table has routes for its protected remote prefixes through the selected tunnel and a terminal prohibit fallback. Destination-specific rules select that table. Neither table/rule absence nor changed kernel priorities can authorize traffic because the independent guard still drops non-XFRM payload. Selection changes replace the exact owned route tuple while guard permission remains no broader than the verified candidate set. No ECMP; engine/reducer contract owns tunnel preference and hold-down.

Persist reservation and protected manifest before the first host mutation. Persist every potentially applied obligation before issuing its command. Record results only after independent readback. A timeout is unknown outcome and retains the obligation. Startup loads durable manifests, reinstates/verifies deny guards, inventories owned objects, then asks the control plane for current authority. Disk state cannot reactivate. Unknown orphan markers, corrupt journal or collision stop activation and surface a repair condition; do not guess ownership or delete foreign objects. Packaging must run guard recovery before enabling node-managed forwarding/daemon initiation. Unsupported boot ordering cannot advertise runtime capability.

## Disable, delete and cleanup finalization

Control plane records possible delivery before releasing secrets. Cleanup authority is an authenticated assigned-node obligation with a unique cleanup ID, current desired revision and delivered high-water mark. Never-delivered connections may retain the existing immediate disabled-delete behavior. A changed/revoked certificate is not positive cleanup proof.

Cleanup order is: persist cleanup obligation; remove payload permits atomically; verify denial including established traffic; prevent new initiation; unload owned connection and credentials; terminate every owned IKE/CHILD SA including rekey overlap; read back absence of owned daemon configuration/credentials/SAs and kernel policies; remove only exact owned active routes/rules/interfaces; drain scoped protected conntrack and verify the required absence; persist the completed receipt. Retries retain identifiers and tolerate absence but refuse identity mismatch. No CP acknowledgement on command-return success alone.

Safety-only refusal guards may remain after forwarding cleanup. A final receipt must explicitly include their immutable manifest digest and durable owner. They contain no permit entries, loaded secret, initiation capability or forwarding path. They are not an orphan resource and must survive restart. Do not release/recycle their ownership identifiers or remote-prefix reservations merely because active resources disappeared. A future authoritative assignment can supersede/transfer the guard under the same serialized deny-first protocol; old cleanup cannot delete a successor guard.

Removing the final protection for a deleted remote prefix changes the promise that continued local traffic cannot fall back to cleartext. This is a product lifecycle choice, not a routine file-cleanup decision. Recommended default: retained denial and nonsecret reservation until authoritative supersession; no force-ack, TTL-based forget or deprotection endpoint in this slice. If product chooses resource release instead, specify an explicit protection-end event and user-visible semantics before implementing it.

## Required real-kernel packet proof

Use only a root-approved disconnected disposable Linux fixture. This paper does not create objects. The fixture needs a local LAN endpoint, gateway, two independent encrypted peer paths, remote endpoint and an underlay sink/capture capable of detecting forbidden plaintext. A positive endpoint handshake plus negative underlay capture distinguishes encrypted delivery from an accidental ordinary route. Keep synthetic keys out of logs/artifacts; assertions record packet identity/counters and sanitized outcomes only.

| Scenario | Required evidence |
| --- | --- |
| Allowed grant | Real payload reaches remote and returns through either authorized tunnel; tunnel/ESP or NAT-T counters advance; no matching inner plaintext at underlay sink. |
| Denied grant / port / source | No remote delivery, exact denial counter advances; wrong-source LAN and wrong-source tunnel injection both denied. |
| Host OUTPUT | Allowed explicit host grant works; absent grant and disabled state deny even with a viable ordinary default path. |
| Established revocation | Maintain a real flow, revoke its grant/disable connection, prove subsequent packets stop despite existing conntrack. |
| SA, interface or route loss | Independently delete each fixture-owned object during traffic; allowed flow stops or switches only to verified backup; underlay receives no inner plaintext. |
| Failover | Lose selected path, observe bounded switch to verified second path without broader permissions; both-down remains denied. |
| Apply/observe failures | Failed nft replacement, failed readback and ambiguous daemon operation cannot open a path or produce success receipt. |
| Restart/crash | Kill node at every durable stage; guard survives or recovery precedes forwarding, no disk-only activation; repeated cleanup converges. |
| Coexistence | Existing unrelated WG, FQDN-marked, native LAN/CNI and host traffic behave identically; no foreign routes/rules/marks removed. |
| Cleanup | Exact owned SAs/config/secrets/active kernel objects and scoped flows absent; safety guard remains, receipt matches current obligation; stale receipt rejected. |

Unit/mutation tests precede code, but cannot replace this matrix. Save fixture identity, exact artifact hashes, commands, relevant sanitized readbacks and positive/negative packet assertions. An empty kernel inventory, SA-established event or candidate boolean does not close S2S-2 runtime acceptance.

## Decisions and implementation work

Routine engineering choices: private table name and hook priorities after collision checks, bounded allocator probing, exclusive locking, strict codecs, fsync stages, static errors, exact cleanup retries and no-mark initial static routing. These need review/test evidence, not repeated user permission questions.

The user approved retained safety guards and range reservations after exact tunnel cleanup; the approved contract is in [cleanup disposition](S-S2S-2-cleanup-disposition.md). Align receipts with immutable delivery/cleanup IDs and the delivered high-water mark in [runtime delivery](S-S2S-2-runtime-delivery.md). No third option silently removes necessary protection. Remote-prefix compiler projection preserving existing explicit grants is routine integration; do not request a new product choice for it. Any future expansion to implicit host/device/mesh permission is outside this initial scope, not a blocker to implementing explicit-grant enforcement.

Engine/library packaging choice is tracked by the engine lane. Lab mutation is a separate execution boundary owned by root. No production capability1 until the actual packaged runtime and required enforcement/traffic gates pass.

Primary source: [strongSwan XFRM routing documentation](https://docs.strongswan.org/docs/latest/features/routeBasedVpn.html) explains interface-ID binding, missing-interface behavior, daemon route ownership and underlay-loop considerations. The guard, journal, allocator and finalization rules above are Tunnex design requirements rather than guarantees from that engine documentation.

## Next bounded enforcement implementation

Implement `RenderGuard(GuardIntent) (GuardManifest, error)` as pure code first, with typed canonical prefixes, directional compiled grants, exact observed interface indices and current revision. Return deterministic nft text plus a digest over the typed semantic manifest; no user strings become nft expressions. An empty/disabled permit list still renders both destination refusal and remote-source anti-spoof protection. Reject mixed families, invalid tuples, duplicate/overlapping ownership and unsupported grant protocols. Renderer has no filesystem/process/CP dependency.

Then implement a separate adapter which inspects the owner marker before applying one atomic `nft -f -` transaction, reads the complete owned table through bounded JSON output, and compares semantic hooks/priority/policies/sets/rules against the manifest. Ignore only documented dynamic counters/handles when matching semantics, never unknown expressions. Readback of a comment/digest alone is insufficient. Do not accept a receipt supplied by external callers. Mutation tests must kill removal of each guard hook, established-flow recheck, index ownership match and policy predicate.

The first isolated packet fixture can use fixture-owned static XFRM state solely to exercise the guard, independent of engine choice. Test real encrypted allowed UDP/TCP, denied port/source, local OUTPUT, established revocation, SA removal, XFRM-interface removal and route removal with an intentionally viable cleartext fallback. This qualifies the enforcement primitive, not IKE, provider compatibility, production integration or two-tunnel completion. Root must approve the fixture execution boundary before it creates any objects. Subsequent engine integration repeats the packet cases using actual negotiated SAs and adds rekey/failover/restart proof.

## Required bounded authority expiry before production activation

The pure renderer now includes kernel timeout sets, but remains unqualified for production until actual expiration and packet denial pass. Failed replacement or node crash can leave old permits and SAs alive. Refusal guards persist; every permit depends on expiring authorization.

The delivery paper defines fresh nonce-bound authority with a maximum60second TTL. The process-local helper anchors its deadline to monotonic request START, subtracts elapsed time and a positive installation budget, and consumes responses once. No wall-clock replay or receipt-time-plus-TTL. Journal replay cannot recreate authority. `GuardConnection.PermitFor` receives only the remaining duration immediately before the current installation. Negative or above60second values refuse; whole-second flooring makes zero/subsecond values deny-only. Retries recompute remaining authority rather than resetting TTL. Applying code must recheck after command/readback and refuse success if expired.

Each connection owns a named `iface_index` timeout set `lease_<connection UUID without hyphens>` with60second default; current indices have explicit element timeouts equal to rounded remaining authority. The atomic transaction adds the set, flushes prior elements, then adds only current members. Every forward, reply, host OUTPUT/input-reply and postrouting accept requires matching that connection's unexpired membership. Disabled/no-lease intent clears membership and renders no accepts. Permanent source/destination/tunnel-interface drops never expire.

`NFTJSON` carries atomic commands; `ExpectedJSON` carries full semantic state including set type, timeout flag, configured timeout and element identities. Native `expires` is bounded dynamic evidence, not a field to erase indiscriminately: compare against authorized remaining lifetime, require live membership for an applied permit receipt, and refuse missing/expired/widened elements. Native nft1.1.3 rejected the provisional datatype name `ifindex`; regression corrected it to `iface_index`. Native nft1.1.3 JSON resolves interface indices to names even with `-n`, while `-n` changes conntrack states to numeric values. Use default `nft -j` and the exact independent before/after kernel interface mapping; unknown or changed names refuse. The verifier retains all base-chain and per-chain rule ordering, grouping definitions as the kernel lists them. The upstream JSON manual specifies set timeout seconds; actual deployed timer behavior still requires native verification. [libnftables JSON schema](https://manpages.debian.org/bookworm/libnftables1/libnftables-json.5.en.html).

Kernel acceptance includes failed replacement and hard process kill during traffic: packets stop by the authorized bound without userspace cleanup, refusal survives, and restart without fresh CP authority cannot resume traffic. The expiry bound is active kernel elapsed time, not wall time while the host is suspended. Observed resume invalidates process authority and restores refusal before further controller permits. Explicit revocation aims for immediate denial; failure remains pending and bounded by the qualified active-time expiry. Cleanup requires exact absence/denial evidence, never elapsed time alone.

## Native guard qualification evidence (local only)

On the verified strongSwan qualification ARM64 image, nft1.1.3/iproute2-6.15.0 installed the actual JSON transaction inside the fresh `tunnexs2sguard0924` network-none container. `TestGuardLinuxReadback` verified deny-only semantics, repeated replacement with a30second timed interface member, exact bound interface names and kernel identity stability; an injected extra permit was refused. The local harness removed only its captured container. Evidence: `/private/tmp/s2s-guard-lab-native.log`; focused readback/renderer/lease race gate: `/private/tmp/s2s-guard-integrated-race.log`. Three readback mutants (semantic comparison, expiry bound, interface mapping) failed behavioral regressions in `/private/tmp/s2s-guard-readback-mutations.log`.

Native checks found and fixed invalid `ifindex` datatype, immutable existing chain comments on refresh, object listing order and interface-name rendering. The owner marker is atomically recreated after table flush, with complete readback required. These are real object/readback checks, not encrypted-packet acceptance. Actual traffic qualification subsequently found the physical-interface XFRM postrouting pass needs a precisely bound encrypted-egress permit; the initial renderer blocks valid encrypted payload at that pass. No production readiness/capability is earned from object proof.

### Timer qualification limit

The current upstream nft element expiration helper compares against `get_jiffies_64()` ([kernel source](https://github.com/torvalds/linux/blob/master/include/net/netfilter/nf_tables.h)). Kernel documentation distinguishes monotonic time, which stops during suspend, from boottime, which includes suspended time ([ktime accessors](https://docs.kernel.org/core-api/timekeeping.html)). These source facts do not prove a deployed VM's pause/resume behavior. Normal running-kernel expiry tests must therefore remain separate from suspend/pause qualification; do not advertise a wall-time revocation bound across suspend from the current helper or a Docker process-pause test. The local fixture does not suspend the shared VM or host. This qualification makes no wall-time expiry guarantee across a suspended host. Permanent cleartext-refusal rules remain installed during sleep and resume; an observed boot-clock/monotonic discontinuity invalidates the process receipt before further controller grants. This detection does not claim to run before the first resumed kernel packet. The original bounded lease contract is active running-kernel elapsed time; adding a suspend-independent per-packet clock mechanism would be separate engineering scope.

The native `TestGuardLinuxDNATEscape` also passed in a separate network-none fixture with no host mounts. An OUTPUT DNAT baseline delivered to an alternate loopback address; production guard installation blocked the same path and advanced the exact original-destination/DNAT refusal counter. Removing original-tuple protection with a Go overlay caused this real-kernel regression to fail behaviorally. Logs: `/private/tmp/s2s-guard-nat-native.log`, `/private/tmp/s2s-guard-nat-native-mutation.log`. All newly captured containers were removed; no default project or shared ruleset was touched.

## Post-NAT refusal evidence

The renderer now owns an additional refusal-only `postnat_guard` at postrouting priority300. It matches both current and original protected remote source/destination against DNAT/SNAT status and grants no forwarding authority. This closes the previously documented SNAT99/100 observation gap; independent platform qualification must still refuse unqualified later modifying hooks.

`/private/tmp/s2s-engine-late-snat-red.log` failed the exact late-hook receipt before implementation. `/private/tmp/s2s-engine-late-snat-green.log` then proved real encrypted forwarded TCP/UDP baseline, denial with fixture SNAT99, a positive exact postnat SNAT-drop counter, and restored encrypted TCP/UDP after removal. The fixture used the pinned ARM64 package plus the rebuilt renderer test binary, synthetic in-memory credentials and captured isolated resources, all removed afterward. This does not substitute for the final integrated production binary qualification.
