# S20.5 HA acknowledged-base reuse

Decision, 2026-09-06: implement the bounded ordinary-authority replay correction
under the user's essential-fix and targeted-acceptance direction. This is not
permission to bypass a required member's acknowledgement.

## State boundary

`DesiredState.Version` is the notification/watch cursor. Both CP and node
canonical base hashes already exclude it. An armed node already accepts an
ordinary response without new authority when its full base hash is unchanged.
The CP nevertheless minted a fresh ordinary authority on cursor-only changes,
making owner renewal wait for an absent standby to acknowledge unchanged data.

For an **already acknowledged latest ordinary maintain-fence authority**, reuse
the existing immutable delivery and receipt when the candidate differs only in
the watch cursor. Keep the original authority revision, base version, hash and
payload digest; never synthesize or rewrite an acknowledgement. Require exact
canonical identity, full base hash, complete classifications and pool promotion
generations. The existing locked topology, accepted-scope and leader checks
remain mandatory. Changed content, scope or generation still requires new
authority and the existing full-member acknowledgement barrier.

Unacknowledged deliveries retain exact-version replay and expiry behavior.
Transition arm/unfence replay remains strict. Do not select a historical receipt
behind a newer delivery. Do not change lease TTLs, omit standby checks, alter
node fencing, replace versions with hashes, or introduce a protocol/schema
migration for this repair.

## Verification and limits

Add a regression through the actual maintenance/runtime/lease store: repeated
cursor-only changes with a silent standby must renew the healthy owner without
new base deliveries. The paired real-content change must block renewal until
the final exact acknowledgement. Retain store-level transition, expiry and
classification tests and run affected tests in both API editions.

The returning startup pending-authority mismatch is a separate delivery case;
this decision does not authorize suppressing mismatches, relabelling response
versions or adding generic startup recovery. Investigate and record its smallest
safe correction separately if still required. Independent review and targeted
AWS standby/owner failure proof remain prerequisites to a PR.
