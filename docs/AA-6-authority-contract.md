# AA-6 staged publication authority

Status: **In development**. This contract adds publication to the accepted AA-0–AA-5 authority; it is not publication or readiness evidence.

The administrator saves the application, checks its exact saved connection, configures explicit access, then reviews the immutable revision, browser hostname, connector and session policy. Publication requires named manage permission, eligible entitlement, organizational opt-in, a current independent browser connector capability, a succeeded origin check and production domain/TLS prerequisites. An origin-check capability alone cannot qualify browser serving.

`POST /applications/{appId}/publication-operations` binds expected application version, revision, digest, succeeded check ID and caller UUID idempotency key. The server retains one pending operation per application, a distinct browser generation and a server readiness request/deadline, independently of the active publication. A repeated key with identical input returns the same operation; conflicting reuse refuses. Operation-ID and idempotency-key readback recover uncertain outcomes. Operations last at most 60 seconds. The reviewed origin check must remain at most five minutes old and retain the current authenticated gateway certificate serial; historical unstamped checks require a fresh check.

Readiness is obtained through the exact pending browser-purpose channel. It performs a fresh bounded origin probe; activation requires that proof no more than ten seconds old, plus the current assigned certificate and independent version-one browser capability reported within 30 seconds. The pending channel, desired assignment, operation and readiness request must all identify the same immutable tuple. No browser route lookup, human launch or app request can serve a pending revision.

The trusted dedicated proxy also performs a fresh public app-host DNS/TLS probe to a bounded, short-lived cookie-free challenge served by that same proxy instance. Challenge correlation includes the server readiness request and a separate instance token; a valid certificate at a different proxy is insufficient. DNS checks every answer under safe public destination policy, dials a validated literal address, uses the exact hostname for TLS verification and system roots, and refuses redirects/environment proxies. Probe bounds are five seconds and four KiB. Local qualification may explicitly inject owned fixture networking/trust into tests; production has no trust or destination bypass. Console and application domains must satisfy the same known public suffix/separate registrable-domain prerequisites as the proxy.

Activation rechecks the reviewed version/digest/check, operation/deadline, settings/license, current gateway/certificate/capability, proxy credential version and both readiness proofs in the transaction that swaps active authority. Pending/active generations coexist under the existing bounded pools. Ordinary certificate rotation for the same trusted gateway preserves the immutable active revision. Browser channels and serving lookup refuse the old certificate and unavailable capability until the current certificate has a fresh independent browser report; pending activation still requires its exact current-certificate readiness proof. Failed, canceled, expired or stale staged edits leave the previous active revision serving. Successful activation retains operation/history and invalidates old exact serving authority; old streams drain under their finite leases.

The publication view returns active authority independently from pending/latest operations and browser capability. UI failure states distinguish draft save, connection-check result, pending publication, active revision and withdrawal. Consequential controls use generated requests, exact version guards and explicit confirmations. A timed-out request triggers retained readback before a new attempt.

Disable remains available after entitlement loss. Its expected application version and expected authority version (zero before first publication) guard both pending-only and active states; it cancels pending work and commits immediate authorization withdrawal independently of origin health. Cancellation addresses the exact operation/version. Re-enable stages a fresh operation. Rollback creates a new reviewed draft from a previously activated immutable revision, then requires current checks/readiness; it never activates an old row blindly.

Archive requires durable disabled state and confirmed withdrawal. Confirmation follows a monotonic five-second wait started after successful disable commit, then is persisted against the exact disabled authority version/generation. Restart repeats the full wait; wall-clock age alone is insufficient. Gateway/proxy acknowledgments provide extra evidence but an offline component cannot indefinitely block archive after qualified finite authority expiry. Archive retains revisions, operations, audit and exact hostname ownership; hostname reassignment is unavailable in this release.

Acceptance requires actual publication/readback through the native proxy/connector, negative prerequisite and stale-review cases, failed pending edits preserving active service, concurrent/idempotent operations, timeout recovery, restart persistence, disable during stage/outage/license loss, and safe archive/rollback. AA-7 supplies complete withdrawal timing, events, packaging and restore qualification; AA-8 supplies the full supported browser/application journey.
