# Worker and skills implementation evidence

Decision paper: [worker and scoped skills](S-sandbox-worker-skills-decisions.md). Public creation remains closed.

Worker wiring is implemented in the server composition root and lifecycle API wake-up hooks. It starts with no qualified adapters and reports dormant; it cannot process a peer or confer provisioning availability. Qualified injection would run an initial scan, bounded100-item serial batches, five-second periodic/wake retries,30-second per-item cancellation and UUID keyset traversal that advances past failed items. Per-sandbox durable leases still fence replicas. Unit/race tests prove dormant workers perform no inventory/provider work, failed early IDs do not starve later batches, startup scanning and cancellation work. Start reconciliation must reuse the same per-sandbox lease before it is added.

Migration0168 persists immutable organization-bound skill revisions, explicit template/revision allowlists and immutable selected revision/configuration in sandbox create intent. No catalog is seeded or externally published. Admission canonicalizes up to16 selections, validates instruction SHA256, bounded metadata/configuration fields and approved choices, checks skill network requirements fit inside requested/template scope, and includes selection in idempotency hashing. Resume revalidates current revision availability. Disabled/disallowed selected revisions withdraw bootstrap eligibility, runtime authentication and policy projection. Catalog JSON returned to users excludes instruction bodies; no secret/free-text/script/package configuration API was added.

Approved bundle preparation is implemented and unit-tested: UUID-only relative paths, exact approved instruction digest validation, inert JSON configuration, deterministic content digests and no filesystem/install execution. It is not an installed skill or qualification of workspace delivery. Browser creation UI has template-filtered skill checkboxes and bounded choice controls, clears selections when template changes, sends selected immutable revision/configuration and keeps unavailable configuration disabled. API refuses selected skills without the separate materialization readiness hook; main supplies no such hook.
