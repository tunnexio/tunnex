## E. saveCreds ORDERING — RULED REAL. The comment is wrong AND the order is wrong.

**Second instance of a comment on this function vouching for a property the code lacks** (pass 1 #11 was the
first). There is **no boot-time pair check** — `grep X509KeyPair apps/node/cmd/agent/main.go` returns nothing.
The only pair validation is inside `control.NewClient` (`client.go:90`), whose failure path is `os.Exit(1)`.

**The comment** (`main.go:441-442`): *"the KEY is renamed LAST … if the sequence is interrupted, the old key
still matches the old certificate and the agent remains recoverable."*

**Both halves fail.** Order is `ca.pem`, `cert.pem`, `key.pem`. An interruption between the second and third
rename leaves **NEW cert + OLD key** — the old certificate is already gone, so "the old key still matches the old
certificate" is false on its face. And the resulting state is the **unrecoverable** one:

| interrupted state | what `Decide` does | outcome |
|---|---|---|
| **NEW cert + OLD key** (today's order) | the new cert is **valid**, so `UseStored` | `NewClient` → `X509KeyPair` fails → `os.Exit(1)` → restart → **identical state** → CrashLoopBackOff. `Decide` never reaches `Recover`, because nothing about the certificate is expired |
| **OLD (expired) cert + NEW key** (key first) | expired → **`Recover`** | `attemptRekey` runs, the pending key file still exists (`saveCreds` removes it only at the end), the fingerprint identity is available → recoverable |

**Ordering alone is not the whole fix.** In the RENEW path the old certificate is still valid, so cert-last gives
old-valid-cert + new-key — a mismatch that also lands in `UseStored` and crash-loops. **The robust fix is a
pair check at load that routes a mismatch into `Recover` instead of `os.Exit`**, since a mismatched pair is
precisely a case proof-of-possession can repair.

**Ruled: REAL. Owed a red.** The comment must be corrected in the same change, not left describing an intent.

## TWO VACUOUS CHECKS WERE PRODUCED WHILE RUNNING THIS AUDIT, AND BOTH WERE CAUGHT

Worth recording because the audit was itself an exercise in *could this check have failed?*

1. **`git show` failing into `2>/dev/null`** made `grep -c` count an empty stream, so the first count reported

   result across a case with a known-different answer is the tell.
2. **zsh's `:a` history modifier** ate the path: `"$c:apps/..."` expanded to `${c:a}` + `"pps/..."`. Caught by a

independently.** A check that cannot distinguish its cases reports agreement, and agreement reads as success.

**Why it is not urgent:** the restore code is edition-independent, so its behaviour cannot differ between the two.

# REGISTERED — the out-of-pool restore loses the audit trail (C#14's sibling, filed with F3)

**Filed here beside F3 deliberately: same shape.** F3 was *"a re-homed device renders perfectly fresh while its
config names a gateway that will never serve it"* — the system knows something changed and the surface does not
say so. This is the same failure in the address tier.

When a restore reclaims a **taken** address it reports `OldIP`, so the change is auditable. When it refuses an
**out-of-pool** address it clears `old` (`restore.go:158`) to force a fresh allocation — and `OldIP` comes back
**empty**. A user stranded by a pool shrink gets a new address with **no record of what they had**, which is
precisely the population most likely to ask.

Not folded: clearing `old` is how the remedy forces reallocation, and reporting it needs a separate field rather
than a reuse of that one. **Trigger: the next change to `RestoreResult`, or the first support request asking what
address a restored device used to hold.**

# A NOTE ON THE THREE REDS, since it inverts everything else catalogued today

**Two of the three were WRONG FIRST and failed against working fixes** — C#14 asserted an `OldIP` the remedy
never promised, C#9 omitted `transport='openvpn'` so the certificate tier never engaged.

**That is the SAFE direction, and it announces itself.** A test that is wrong by failing gets investigated in
minutes. Every mechanism catalogued today — half-fold, tautological guard, fixture-restates-production,
true-by-structure, `[no tests to run]` — is dangerous precisely because it is wrong by **passing**. **The
errors that cost this epic weeks were the ones that went green.**
