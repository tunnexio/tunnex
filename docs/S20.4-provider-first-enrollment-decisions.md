# S20.4 UI slice — Provider-first Kubernetes enrollment

Status: **LOCKED — FOUNDER APPROVED 2026-08-28**.

Founder disposition: user requirements **U1–U6 remain LOCKED** and new
decisions **D1–D3 are LOCKED as recommended**. Product implementation remains
subject to the repository's paper-first story sequence and the founder's
separate no-commit, no-push-until-preview instruction.

This paper defines the Kubernetes connectivity UI only. It does not authorize
product code, schema or generated-output changes, `PLAN.md`, a commit, push,
deployment, or merge. The implementation must stop at a local desktop and
narrow preview for founder approval.

## Measured current boundary

- `RegisterClusterModal` is one flat form for Site, connector, cluster name,
  VIP range, Service CIDR, and DNS zone. It has no provider or managed-service
  context.
- `RegisterK8sClusterRequest` and `K8sCluster` have no provider/platform field.
  Provider identity therefore cannot truthfully be shown after enrollment
  without an additive contract, and existing rows must never be guessed.
- `ExposeServiceModal` accepts namespace, Service name, protocol, and one port
  as free text. Current OpenAPI has no connector-reported namespace/Service/
  port inventory read.
- The current page has real Site, node, cluster, and exposed-Service reads.
  There is no AWS, Azure, or Google account integration and no cloud resource
  discovery contract.
- The shared `Modal` already has a real `wide` size, focus entry/trap/return,
  Escape dismissal, and a portalled overlay. The new design should extend this
  established primitive rather than introduce a second dialog system.
- S20.4 keeps governance on Access. Kubernetes may enroll clusters and expose
  exact Services, but it must not receive scope grantees, pending reviews, or
  approve/reject actions through its broad `org:view` read.

## Locked user requirements

### U1 — Provider comes first and determines the platform choice

**LOCKED by the founder.** The first control is one semantic single-select
provider-card group with these initial paths:

| Provider card | Platform/service choice |
| --- | --- |
| Amazon Web Services | Amazon Elastic Kubernetes Service (EKS) |
| Microsoft Azure | Azure Kubernetes Service (AKS) |
| Google Cloud | Google Kubernetes Engine (GKE Standard) |
| Self-managed | Kubernetes |

Changing provider clears every dependent platform, connector, cluster, and
inventory selection. GKE Autopilot and unlisted self-managed distributions are
not silently offered as if supported.

### U2 — Real cloud brand marks, committed locally

**LOCKED by the founder.** AWS, Azure, and Google Cloud cards use recognizable
brand marks as local, code-native SVG components/assets. Self-managed uses a
neutral infrastructure mark. No CDN, remote image, runtime logo package, emoji,
or generic letter tile is the production result. Adjacent visible provider
text remains the accessible name; decorative duplicate marks stay hidden from
assistive technology. Asset provenance and applicable brand-use terms are
recorded before commit.

### U3 — Provider catalog is not cloud discovery

**LOCKED by the founder.** Provider and platform options are a small
code-owned support catalog used for installation guidance and filtering. Site,
connector, cluster, namespace, Service, and exact-port choices come only from
the current control-plane or an authenticated connector inventory contract.

The UI never fabricates a cloud account, region, EKS/AKS/GKE cluster, Service,
port, readiness state, or zero count. No cloud credentials are requested. A
failed, stale, unauthorized, or unavailable inventory read is distinct from a
successful empty result.

### U4 — Inventory-first exposure with a manual compatibility path

**LOCKED by the founder.** After a connected cluster exists, the primary flow
is cluster → namespace → Service → one or more exact protocol/port children.
Each downstream searchable dropdown is disabled until its parent is selected
and has explicit loading, ready, empty, stale, and error states.

The current manual namespace/name/protocol/single-port route remains under a
clearly separated **Advanced manual entry** disclosure. It uses the existing
endpoint and server validation, makes no “verified inventory” claim, and is
not preselected or mixed into the verified result list.

### U5 — One polished, accessible wide enrollment modal

**LOCKED by the founder.** Enrollment uses the existing wide modal shell:

- provider cards across the top;
- provider-filtered platform/service and real connection choices below;
- advanced network values grouped separately from the common path;
- a compact context/review panel on wide screens and an in-flow review block
  on narrow screens; and
- persistent Cancel and final enrollment actions with accurate busy/error
  states.

Cards are native radio semantics, fully keyboard operable, visibly focused,
and expose selected state without relying on color alone. Every field has a
programmatic label and inline error association. Focus remains trapped while
open and returns to the opener on dismissal. Reduced motion and narrow layouts
must retain the same information and action order.

### U6 — Preview before any repository publication

**LOCKED by the founder.** A production-shaped local preview with desktop and
narrow screenshots is required before commit. Tests do not approve the visual
design. No commit, push, PR, deployment, or merge occurs before explicit
founder approval of that preview.

## Founder-approved implementation decisions

### D1 — Persist truthful provider/platform presentation metadata

**LOCKED.** Add optional server-validated enums to the
OpenAPI-first cluster contract:

- provider: `aws | azure | gcp | self_managed | unknown`;
- platform: `eks | aks | gke_standard | kubernetes | unknown`.

Existing rows read as `unknown`; migrations never infer a provider from names,
CIDRs, Sites, connectors, or endpoints. New UI registrations send one allowed
provider/platform pair. These fields are presentation and installation context
only: they do not authorize, discover, attest, place, or grant anything.

Because an operator can select the wrong presentation metadata, add one
`k8s:manage` edit call site on cluster detail rather than forcing destructive
deregistration. The server validates the pair and writes a bounded audit event.
Old clients may omit both and remain compatible; partial or invalid pairs are
rejected.

### D2 — Keep the initial support catalog intentionally narrow

**LOCKED.** V1 offers exactly EKS, AKS, GKE Standard, and
generic self-managed Kubernetes. EKS Anywhere, OpenShift, Rancher/RKE, k3s,
GKE Autopilot, and additional managed services are deferred until their
installation/runtime behavior is qualified. Adding a label is not evidence of
support.

### D3 — Provider defaults are guidance, never submitted facts

**LOCKED.** The selected platform may change explanatory
copy and show example commands, but it must not silently choose or submit a
Service CIDR, VIP range, DNS zone, Site, connector, namespace, Service, or
port. Network values remain explicit operator input validated by the server.

## Ownership and absence-question acceptance

Every connectivity mutation must have a released call site and accurate
impact copy:

| Mutation | Kubernetes call site | Required result/impact truth |
| --- | --- | --- |
| Register cluster | Provider-first enrollment modal | Registered is not connected or ready; show the actual connector state. |
| Edit provider/platform metadata | Cluster detail, only if D1 is approved | Presentation changes only; no traffic or access-policy effect. |
| Set/change connector | Cluster detail | State which connector owns endpoint observation and that reconciliation may withdraw before serving. |
| Inventory-backed exact-port exposure | Cluster/Service flow | Show exact selected children; no wildcard, inferred sibling, or partial-success claim. |
| Advanced manual exposure | Advanced compatibility disclosure | Mark input unverified and preserve typed server refusals. |
| Unexpose exact child | Service detail/action | State VIP/DNS/policy withdrawal and sibling-child effect from S20.4. |
| Deregister cluster | Cluster detail/action | Refuse while scopes exist and direct the operator to Access cleanup. |

Scope creation, enable/disable/delete, and approve/reject remain on Access with
`k8s_scope:*` permissions. The Kubernetes page may link an authorized operator
to Access, but cannot become a second governance owner.

## Proof and stop condition

Before the preview is presented:

- DOM tests prove logo presence, radio/keyboard/focus/selected behavior,
  cascading reset, permission absence, and loading/error/stale/empty states;
- API tests prove provider/platform pair validation, legacy omission, no
  inference, cross-org isolation, and truthful metadata edit if D1 is approved;
- inventory tests prove reporter ownership, freshness, error-versus-empty,
  exact ports, and that manual entry never receives a verified badge;
- desktop and narrow local screenshots show provider cards, a selected service
  path, the review context, and the advanced compatibility path; and
- the absence table is rechecked against every mutating endpoint and every
  destructive response/FK effect.

The slice then stops for founder visual approval. Repository gates, live-wire
qualification for each claimed platform, commit, push, PR, deployment, and
merge remain separate later approvals.
