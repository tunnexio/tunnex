# Fixed-scope live packet runner preparation

This is source preparation only. No SSH, target observer, packet, grant or cloud mutation was executed by this work. Run only after the owner authorizes a specific allow/default-deny checkpoint and the runtime has independently supplied current SA, route and full-guard evidence. The provider owns normal API grants; this runner creates none.

`deploy/ipsec/gcp-cloud-packet-check.py --profile classic|ha --expect allow|deny --evidence /existing-private-0700-dir/new-receipt.json` connects only through the designated `cyberking9560@34.131.23.179` bastion. The existing Google authentication key stays there. Client and target SSH use the exclusive previously authenticated public pins, exact instance aliases and strict host-key checks. Existing pin files must be owned0600 regular files and their public fingerprints must exactly match the retained authenticated receipts; drift refuses before any target/client command. The immutable client is `4751969643435150303` / `10.70.0.10`; HA target is `7595462031766211538` / `10.80.0.10`; Classic target is `139156170322758560` / `10.81.0.10`.

The captured original startup service returns HTTP200 with `tunnex-gcp-private-application` plus newline for every GET on TCP8080 and echoes the exact UDP payload on port9000. It has no application receive counters. The runner sends one small UUID-tagged request for each protocol, records request/response hashes and elapsed time, and performs no retries. HTTP proves the known exact marker; UDP proves the exact unique payload and endpoint.

A bounded target `sudo python3` raw Ethernet/IPv4 observer performs a local self-control against the same retained service, binds only the interface currently assigned the exact target private IP, and emits READY before the client starts. It counts only the fixed source/destination/port tuple and exact request nonce. STOP drains queued frames before reading kernel capture-drop statistics; the observer must stop by that handshake and have zero capture drops. No file, listener, service or firewall is changed on the target. The process requires existing passwordless sudo, Python3 and iproute2; absence is a refusal, with no installation fallback.

An allow checkpoint requires exact client response and observed exact target request. A deny checkpoint requires client timeout/socket refusal AND zero observed matching tuple frames with a healthy listener control and completed zero-drop capture. A timeout alone is inconclusive. This establishes bounded packet observation; attribution to a particular policy/lease still requires the independent native guard and normal API revision evidence. No capture is stored, and only hashes/counts are returned. It does not prove fragmentation, large payloads, HA failover or production readiness. Relevant fragmented frames or VLAN frames make acceptance inconclusive rather than being silently counted as absent.

Evidence is written exclusively to a new0600 file under an existing owned0700 directory. SSH stderr and response bodies are not printed. The four local source tests exercise exact/foreign tuple and nonce parsing, fixed pin/alias scope and unsafe mode/fingerprint drift, and duplicate JSON refusal; they do not constitute cloud packet proof.
