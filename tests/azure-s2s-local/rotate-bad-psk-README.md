## Revision and permission consequences

Current source rotation increments **desired_revision** and the selected tunnels' **secret_revision**. `ipsec_provider_bindings.configuration_revision` is currently fixed/immutable1 in migration0159; rotation does not update it. The helper checks exact nonsecret network envelope hash/configuration revision before and after and refuses any change. Do not claim a configuration revision bump or automatic deletion of grants from PSK rotation.

Disabling removes current transport authority, and resolver path validity requires an enabled owned connection plus matching configuration revision (`fqdnresources/resolver_ipsec.go`, migration0219). Existing DNS/application grant rows are not equivalent to live authority. Old desired-revision deliveries/status and leases cannot establish the new transport's readiness. After restore, re-read actual normal profiles/grants/current configuration revision, renew/reactivate or rebind only through normal APIs if required, and repeat exact grant/default-deny/revoke/expiry behavior. Do not broad-grant, reuse stale cached addresses as fresh DNS proof, or create synthetic status/capability evidence.

The helper is intentionally bound to the original AA-BGP allocation/network. Different connection/profile/topology or changed normal allowlist requires a separately reviewed helper binding. Private state contains plaintext rollback material by design; keep it0600 and never export it with sanitized receipts.
