# Independent native max-prefix observer

Source-only qualification observer: `apps/node/internal/ipsec/runtime_azure_max_prefix_proof_linux_test.go`. No native or cloud execution was performed for this change. It constructs no controller, adopts no process, writes no journal, and sends only native read commands.

Build the node package test binary for the actual owned Linux architecture. Review and attest that binary's source/hash separately before invoking `TestAzureOwnedMaxPrefixNativeProof` in the actual gateway container with `TUNNEX_AZURE_MAX_PREFIX_NATIVE_PROOF=1`. The observer requires root and a private root-owned, no-symlink file at `/run/tunnex-qualification/max-prefix-binding.json`.

The binding has exactly these fields: `mode` (`baseline` or `absence`), `org_id`, `site_id`, `gateway_id`, `connection_id`, `desired_revision`, `configuration_revision`, `maximum_prefixes` (1 or 8), `namespace_device`, `namespace_inode`, `node_executable_sha256`. Obtain these from fresh independent normal immutable binding and actual container identity reads; never manufacture a receipt from this example. Journal SiteID is present and is checked directly. Absence desired revision must match the actual journal CleanupDesiredRevision.

Success emits exactly one `AZURE_MAX_PREFIX_NATIVE_PROOF ` line followed by typed JSON suitable for private extraction. A failing or skipped test produces no receipt. Retain harness output privately; never substitute harness success text for the typed line. The projection reports actual native counts and actual parsed FRR counters/routes. It does not attest control-plane ACK, Azure advertisements, packets, image identity, or readiness beyond these observations.

The observer validates the whole bounded/checksummed journal, every retained entry/process retirement duty, the full stored guard and withdrawal (absence), exact owned tunnel/SAD/SPD bindings, root socket peer credentials, managed daemon version, independent FRR VTY counters/RIB, executable identities and namespace. Two complete observations bracket unchanged process/socket/config/journal identities. Any extra candidate route, duplicate IKE, partial SPD, counter disagreement, missing route or changed observation refuses baseline.

Charon must be a direct child of the attested node. Every VICI dial checks the initial socket device/inode/mode before and after connecting, as well as the actual root peer PID. FRR reads send only the two fixed show commands through that same credential-verified connection, using the NUL-terminated command/three-NUL-plus-status reply framing in [FRR's VTY client source](https://raw.githubusercontent.com/FRRouting/frr/frr-10.2.1/vtysh/vtysh.c). They do not launch vtysh or redial behind the attestation. Bounded malformed/nonzero/truncated replies refuse; no command replay occurs.

The offline fixture contains nineteen retained entries plus one active entry. Retained entries must belong to the same Site and namespace as the observed gateway unless the optional exact historical reboot attestation below applies. Compacted hash history is checksum/chain validated but its omitted individual process identities cannot be independently reinspected. Do not remove or rewrite history.

An optional `historical_boot` binding contains exactly `proof_sha256`, `stopped_journal_sha256`, and `root_attested_host_machine_id`. Root must independently verify these against the original private supervisor proof, original stopped journal bytes and a real current host machine-ID read. The host machine ID is external supervisor input; the observer does not misidentify container machine ID as host identity. Copy unchanged original files privately to `/run/tunnex-qualification/historical-reboot-proof.json` and `historical-stopped-journal.json`.

The original hash-pinned proof must bind the archived journal, the same owner/machine, distinct canonical old/new boot UUIDs, ordered past reboot timestamps and the actual current `/proc` boot. Every exceptional retained entry must match a unique archived DeliveryID with exact Site/contract/ownership/allocation/engines/observed/BGP/restoration fields. Only epoch-zero old-boot entries with unchanged original process identity now recorded cleaned, no reset/absence-only/retired process history, qualify. Their obsolete process directories/PIDs are not adopted or inspected as current objects; the independently attested genuine VM reboot discharges that exact old-boot lifetime. Same-boot or unbound old namespaces refuse. Current native/process/guard and two-pass bracketing remain mandatory. Typed output records matched entry count and pinned hashes; this is historical lifetime evidence, not new restoration permission.

Managed daemon version means the existing `DaemonClient.Inspect` VICI `version` read enforces `6.1.0`; the observer also compares the running executable with the packaged binary hash. It invokes no packaged CLI version probe.

The two-pass identity hash excludes only CHILD `BytesIn` and `BytesOut`, which are checked separately for monotonicity against the exact unchanged IKE/CHILD unique IDs. Counter decreases, missing/duplicate identities or any SA/SPI/selector/reqid/ifID/state change refuse. Each pass still runs all strict native validators. Success records only `traffic_counters_monotonic_advanced` (boolean); refusals separate process/native-identity/BGP/counter brackets without exposing native payloads. Offline counter advancement proves the old full-child comparison could falsely refuse; it does not establish the cause of any historical live refusal.
