`decode-owned-bgp-capture.py` reads an existing private classic PCAP and writes a new private typed projection. It performs no network calls, capture, Azure/API mutation, daemon config change, route refresh, socket interaction or authority manufacture. Constructed wire fixtures qualify the parser only; actual live proof must come from a real capture made by root in the independently attested owned gateway namespace before candidate addition.

The input must be current-UID0600, regular, nonsymlink, at most4MiB in a current-UID0700 nonsymlink directory. Output requires the same private parent and an absent path. Root-produced captures are decoded as root; do not broaden the owner gate for Ubuntu. Supported classic PCAP2.4 link types: Ethernet1 (up to two VLAN tags), Linux cooked SLL113 and SLL2 276; little/big endian, micro/nanosecond timestamps. PCAPNG, truncated snaplen, IPv4 fragmentation, sequence wrapping, conflicting retransmissions, gaps, TCP resets/urgent data, tuple reuse, incomplete/misaligned BGP messages, oversized messages/streams and malformed parsed NLRI/attribute structures refuse the whole projection. No scanning/resynchronizing past arbitrary bytes is allowed. Identical retransmission bytes and out-of-order segments are reconstructed; the event time is when the complete BGP message's bytes had first been observed, using original packet timestamps. A midstream capture succeeds only if its minimum captured sequence begins with an exact BGP marker and all captured messages are complete; this does not establish TCP session start, authentication or completeness before/after capture.

Direction is fixed: actual Azure sources169.254.21.2 or169.254.22.2 to local169.254.10.1, source or destination TCP179. Only exact candidate10.235.77.0/24 advertisements/withdrawals are emitted, including ordinary IPv4 NLRI and IPv4-unicast MP_REACH/MP_UNREACH. The managed BGP config must be independently verified as the normal IPv4-unicast **without negotiated Add-Path** configuration; this decoder has no Add-Path input override and does not infer unknown negotiation from a midstream capture. OPEN extended option encodings and BGP extended messages are unsupported and refuse. It checks selected attribute structure but is not a full RFC semantic validator or checksum verifier (capture checksum offload must not be mistaken for protocol validity).

Root's later authorized capture can use the existing owned tcpdump with a full snaplen and narrowly bound TCP179 filter for the three actual addresses, inside the attested gateway namespace. The decoder does not invoke tcpdump or authorize/perform a repeated prefix experiment. Keep capture private; do not print its packet payload or use raw-byte grep as NLRI proof. IPv4 BGP normally has unencrypted payload only on the owned decrypted transport interface; a host capture of encrypted ESP will not produce candidate events. Capture begun after the earlier UPDATE cannot recover it. A bounded capture stop in the middle of a BGP message will require a new complete capture, not an ignore-incomplete flag.

```
python3 tests/azure-s2s-local/decode-owned-bgp-capture.py --capture /owned-root-0700/candidate-bgp.pcap --output /owned-root-0700/candidate-bgp-projection.json
```

Output records only version/kind, original capture SHA256, link type, capture first/last packet timestamps, packet/message/stream/duplicate-byte counts, fixed candidate, exact peer/action/event timestamp and a fixed scope string. No arbitrary PCAP payload, attributes, other prefixes, ports, hostnames or account material is copied. Console output contains only fixed write-success or generic refusal. Empty events mean the candidate was not observed in this capture; they do not prove rejection or non-advertisement. Specific wire advertisement plus independently fresh neighbor inbound-filter counter/accepted-route readback and exact RIB/kernel absence can support the narrowly stated observed rejection experiment; parser output alone cannot assert FRR consumed/rejected the UPDATE or native authority. Preserve the earlier aggregate-counter-only limitation even if a later capture succeeds.

Bounds:4MiB file,8192 packets,8 directed tuples,256KiB per reconstructed stream,128 candidate events,4096-byte BGP messages. Time strings preserve PCAP precision as nine fractional digits, never replaced with current time or claimed fresh by the decoder. No raw capture gets exported; root retains it privately with its matching digest.
